# 追问推荐 PRD

> 用途：① 与开发对齐追问推荐的生成逻辑、交互规格与提示词；② 交给 Claude Design 按第 4 节调整原型（追问 chips 从输入区移入对话流）。
> 日期：2026-07-09
> 关联文档：[场景切换与工作台联动-设计方案.md](场景切换与工作台联动-设计方案.md)（场景状态模型与输入区布局的上位定义）

## 1. 背景与目标

### 1.1 解决什么问题

- 老师用户输入成本高：备课任务多为多轮打磨（改产出、调难度、补内容），每轮手动组织指令有门槛
- 用户不了解能力边界：很多老师不知道「还能这么问」，追问是随对话进行的轻量能力教育
- 多轮深度不足：给出下一步的具体建议，比空输入框更能推动会话往深处走

### 1.2 产品定位

追问是**锦上添花组件：可以缺席，不能出错**。生成失败宁可不展示，也不给无关或低质建议。该定位决定了第 3 节的降级链和第 7 节的所有边界处理原则。

### 1.3 核心指标

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 追问点击率 | 点击次数 / 展示次数（分类型统计） | 衡量建议质量与相关性 |
| 会话延续率 | 点击追问后该会话的后续轮数，对比未点击会话 | 验证「推动会话变深」的目标 |
| 降级触发率 | 模板兜底 / 不展示的触发占比 | 监控 LLM 主路径稳定性 |

## 2. 追问类型体系

### 2.1 一期支持两类

| 类型 | 编码 | 定义 | 示例 |
| --- | --- | --- | --- |
| 修改当前产出 | modify | 针对右侧工作台当前产出物的调整指令 | 重难点再细化 / 补充教学反思 / 作业改成分层 |
| 场景内延伸 | extend | 同场景下的下一步动作，不涉及切换场景 | 导学案成稿后「配一份预习单」；找资源结果后「只看带解析的」 |

### 2.2 每轮组合规则

- 每轮展示 **2–3 条**
- 有产出物的轮次：至少 1 条 modify，可搭配 extend
- 无产出物的轮次（纯问答）：只出 extend
- **一期硬约束：所有追问必须在当前场景能力范围内可完成**，不得引导用户切换场景

### 2.3 二期规划项：跨场景动作（本期不做）

类型 cross_scene（如导学案成稿后「把这份导学案做成课件」）。一期不做的理由：先让用户在单场景内把事做深，避免追问变成场景跳转的干扰源。

**预留设计**：类型字段枚举中保留 cross_scene 值；二期上线时，点击跨场景追问 = 一次手动切换事件（写入 `场景来源 = manual`，获得豁免期），与路由模型的豁免机制直接联动，链路定义见关联文档第 4 节。

## 3. 生成逻辑

### 3.1 触发时机

- 每轮 AI 回复**完整生成后**触发，异步请求，不阻塞主回答渲染
- 以下轮次**不触发**：系统消息轮（场景切换提示、豁免期确认卡）、错误/失败轮、AI 反问等待用户补充信息的轮次

### 3.2 主路径：LLM 生成

- 主回答渲染完成后发起生成请求，超时上限 **2 秒**
- 输入与提示词见第 5 节，输出为结构化 JSON
- 输出先过代码层质量校验（见 5.3），通过后渲染

### 3.3 两级降级链

```text
LLM 生成 ──失败/超时/校验不通过──→ 模板库兜底 ──未命中──→ 不展示
```

**降级一级：模板库**。按「场景 × 产出物类型」维护静态追问模板，人工审核。示例：

| 场景 | 产出物类型 | 模板追问 |
| --- | --- | --- |
| 写教案 | 导学案成稿 | 补充教学反思 / 作业改成分层 / 重难点再细化 |
| 出卷子 | 试卷成稿 | 换掉最难的一题 / 附上答题卡 / 生成答案详解 |
| 找资源 | 结果列表 | 只看带解析的 / 换个难度 / 整套打包下载 |

**降级二级：不展示**。模板库未命中（新场景、新产出物类型未配置）时，本轮无追问。不做占位、不做加载态。

### 3.4 去重规则

- 与**最近 5 轮已展示**的追问文本去重（含语义雷同，由 LLM 在提示词中约束 + 代码层文本相似度兜底）
- 用户已点击过的追问，本会话内不再生成同款

## 4. 交互规格

### 4.1 位置：对话流内，不在输入区

- 追问 chips 挂在**最新一条 AI 回复（或产出卡片）下方**，属于对话流的一部分
- **与输入区的职责分工**（上位定义见关联文档 5.2）：输入区上方只有场景胶囊一排（会话级状态控制，常驻）；追问是针对上一轮回答的内容建议（轮次级，短命），跟着消息走
- 禁止把追问 chips 放在输入框上方或输入框容器内——与场景胶囊叠放会造成两种语义的胶囊混排

### 4.2 点击行为：直接发送

- 点击 chip 即作为用户消息发出，消息内容为该条追问的 `send_text`（完整指令，见 5.2 输出格式）
- chip 显示 `label`（短文案），发送 `send_text`（完整指令），两者分离：显示要短，指令要完整无歧义

### 4.3 生命周期

- 用户发出新消息（无论手打还是点击追问）后，旧追问 chips **直接隐藏**，不在历史消息中保留——追问服务于「此刻的下一步」，上一轮问完即失效，保留只会制造视觉噪音。任何时刻对话流中最多只有一组追问（最新一条 AI 回复下方）
- 追问生成完成前用户已发出新消息 → 本次生成结果丢弃，不展示

### 4.4 样式约束

- 沿用胶囊视觉语言，但必须与场景胶囊可区分：追问 chips 带 ✨ 前缀图标（现原型已采用），场景胶囊带场景图标
- 最多 3 条，超宽折行；出现时轻量浮现动效，不打断阅读

## 5. 提示词设计

### 5.1 输入变量

| 变量 | 说明 |
| --- | --- |
| current_scene | 当前场景名（找资源 / 出卷子 / 做课件 / 写教案 / 问教材 / 画导图 / 改作业） |
| scene_capabilities | 该场景支持的能力清单（由各场景配置提供） |
| last_user_message | 用户最近一条消息原文 |
| last_assistant_summary | 本轮 AI 回复摘要（长回复截断至 500 字以内） |
| artifact_type | 当前产出物类型（导学案 / 试卷 / 课件大纲 / 资源列表…），无产出物为 null |
| artifact_outline | 当前产出物大纲或结构摘要，无产出物为 null |
| recent_shown_suggestions | 最近 5 轮已展示的追问 label 列表 |
| user_memory | 用户画像记忆（教材版本、年级、学科、偏好难度） |

### 5.2 生成提示词（完整版，可直接使用）

```text
你是「学科网 AI 小博士」的追问推荐生成器。你的任务：基于本轮对话，为老师生成 2–3 条可以一键发送的追问建议。

## 当前上下文
- 当前场景：{current_scene}
- 该场景支持的能力：{scene_capabilities}
- 用户最近一条消息：{last_user_message}
- 本轮 AI 回复摘要：{last_assistant_summary}
- 当前产出物类型：{artifact_type}（无产出物时为 null）
- 当前产出物大纲：{artifact_outline}（无产出物时为 null）
- 最近已展示过的追问：{recent_shown_suggestions}
- 用户画像记忆：{user_memory}

## 生成规则
1. 只生成当前场景（{current_scene}）能力范围内可完成的动作，不得引导用户切换到其他场景。
2. 类型分配：artifact_type 不为 null 时，至少 1 条 type 为 modify（修改当前产出），可搭配 extend（场景内延伸）；artifact_type 为 null 时只生成 extend。
3. 每条建议必须针对本轮回复的具体内容，禁止与上下文无关的泛泛建议（如「还有什么可以帮你」「继续优化」）。
4. 不得与「最近已展示过的追问」重复或语义雷同。
5. label 为 chip 显示文案：4–8 个字，动词开头（如「补充教学反思」）。
6. send_text 为点击后实际发送的指令：一句完整、无歧义、可直接执行的话（如「在导学案末尾补充一段教学反思，包含预设问题与改进点」）。
7. 结合用户画像记忆调整建议（如用户偏好中等难度，则难度类建议默认围绕中等展开）。
8. 语气贴合教研场景，使用老师熟悉的术语（导学案、分层作业、重难点、当堂检测、变式题等）。

## 输出格式
只输出 JSON 数组，不要任何其他文本：

[
  {"type": "modify", "label": "重难点再细化", "send_text": "把导学案里的重难点部分再细化，每个难点补充一个突破策略和一道对应例题"},
  {"type": "extend", "label": "配一份预习单", "send_text": "基于这份导学案，再配一份课前预习单，控制在 10 分钟内可完成"}
]

生成不出满足要求的建议时，输出空数组 []。
```

### 5.3 代码层质量校验（不依赖 LLM 自觉）

输出渲染前逐条校验，任一环节失败即丢弃该条；全部丢弃后条数为 0 → 走降级链：

1. JSON 解析失败 → 整体降级
2. 条数 > 3 → 截断保留前 3 条
3. label 超过 10 字或为空 → 丢弃该条
4. type 不在枚举（modify / extend）内 → 丢弃该条
5. 与 recent_shown_suggestions 文本相似度过高 → 丢弃该条
6. send_text 过内容安全校验（复用主链路安全能力）→ 不通过则丢弃该条

## 6. 埋点

| 事件 | 触发 | 关键字段 |
| --- | --- | --- |
| suggestion_show | 追问 chips 渲染完成 | source（llm / template）、types、scene、round_id |
| suggestion_click | 用户点击某条追问 | type、label、position（第几条）、scene、round_id |
| suggestion_fallback | 触发降级 | level（template / none）、reason（timeout / parse_fail / quality_fail） |

分析口径：点击率按 type 和 source 分维度看（验证 LLM 生成是否显著优于模板）；会话延续率以 round_id 关联后续轮数；fallback reason 分布用于定位主路径不稳定的原因。

## 7. 边界情况与降级细则

1. **LLM 超时（> 2s）**：中断请求，走模板兜底，上报 fallback(timeout)
2. **用户抢先输入**：追问生成期间用户已发新消息 → 丢弃生成结果，不展示、不上报 show
3. **流式回答被用户打断**：本轮不触发追问生成
4. **模板库未命中**：不展示，上报 fallback(none)。新场景 / 新产出物类型上线时，模板库配置作为上线检查项
5. **内容安全**：模板库全部人工审核；LLM 输出逐条过安全校验（见 5.3 第 6 条）
6. **与首页推荐的关系**：首页「老师们在问」和场景冷启动页推荐是**另一套体系**（基于记忆与热门，服务冷启动意图），与追问（基于本轮上下文，服务延续意图）不共用生成逻辑；两者共用胶囊视觉语言，靠图标区分
