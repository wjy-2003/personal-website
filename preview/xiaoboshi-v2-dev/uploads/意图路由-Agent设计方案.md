## 1. 架构概述

采用混合架构（方案 C）：

```
无工作台状态（右侧为场景区首页）
  → 规则层（快速匹配）→ 命中则直接调起场景
  → 未命中 → 独立路由 Agent（全局路由判断）

有工作台状态（右侧已打开某个场景）
  → 规则层（快速匹配）→ 命中则直接处理
  → 未命中 → 当前场景 Agent 先判断（边界判断模块）
      ├─ 能处理 → 场景 Agent 直接处理
      ├─ 明确是别人的 → 直接转场
      ├─ 场景外临时响应 → 通用回答，工作台不动
      └─ 不确定 → 升级给独立路由 Agent 仲裁
```

三层调用关系：

| 层级            | 技术方案           | 调用时机                     | 延迟            | 成本                     |
| ------------- | -------------- | ------------------------ | ------------- | ---------------------- |
| 规则层           | 动作词 + 对象词组合匹配  | 每次用户输入先过                 | <10ms         | 零                      |
| 场景 Agent 边界判断 | 嵌入场景 Agent 提示词 | 有工作台时，规则层未命中             | 与场景处理合并，无额外调用 | 零（复用场景 Agent 的 LLM 调用） |
| 独立路由 Agent    | 独立 LLM 调用      | 无工作台时规则层未命中，或场景 Agent 升级 | 额外一轮 LLM 调用   | 额外 token               |

关键优化点：场景 Agent 的边界判断不产生额外 LLM 调用——它嵌入在场景 Agent 的系统提示词中，作为场景 Agent 处理输入的第一步。场景 Agent 的一次 LLM 调用同时完成"判断这是不是我的活"和"如果是我的活就处理"两件事。

## 2. 右侧区域的三种状态

路由判断需要感知右侧区域的当前状态：

| 状态 | 含义 | 对应 workspace_state |
| --- | --- | --- |
| 意图理解过渡态 | 正在识别用户需求，右侧显示"正在理解你的需求…" | `"processing"` |
| 场景区首页 | 场景选择卡片（找资源、出卷子等），用户可手动选择 | `"home"` |
| 具体场景工作台 | 某个场景已打开（找资源列表、大纲编辑器等） | `"找资源"` / `"问教材"` / ... |

路由 Agent 收到的 workspace_state 为 `"home"` 或 `"processing"` 时走全局路由；为具体场景名时走场景 Agent 边界判断（升级时才到路由 Agent）。

## 3. 规则层

规则层是纯代码逻辑，不涉及 LLM。匹配成功则直接执行，不再调用路由 Agent。

### 3.1 匹配规则

```
规则格式：(动作词集合, 对象词集合) → 目标场景

找资源：(找/搜/搜索/下载/有没有, 试卷/课件/教案/讲义/PPT/资源/文档/素材)
出卷子：(出/组/编/命制, 卷子/试卷/题/测试/练习/单元测试)
做课件：(做/生成/制作, 课件/PPT/幻灯片)
写教案：(写/备/设计, 教案/讲义/教学设计/学案/学历案)
画导图：(画/生成/做, 导图/思维导图/知识结构图/知识图谱)
改作业：(批改/改/讲评/批, 作业/作文/试卷) + 附件存在
```

### 3.2 匹配逻辑

```
1. 分词/提取动作词和对象词
2. 遍历规则表，找到匹配的规则
3. 如果匹配唯一 → 直接调起对应场景
4. 如果匹配多条 → 交给路由 Agent 判断
5. 如果无匹配 → 交给路由 Agent（全局路由）或场景 Agent（有工作台时）
```

### 3.3 规则层不处理的情况

- 短关键词（无动作词，如"三角函数"）
- 混合意图（"找一份试卷，找不到就帮我出一份"）
- 模糊表达（"帮我准备明天的课"）
- 纯知识问题（"三角函数是什么"）
- 轻场景命中（方法指导、写作文等，信号不够明确，需要 LLM 判断）

## 4. 独立路由 Agent

### 4.1 输入定义

```json
{
  "user_input": "用户当前输入文本",
  "attachments": [
    {"type": "image", "filename": "作业.jpg"},
    {"type": "pdf", "filename": "试卷.pdf"}
  ],
  "workspace_state": "home" | "processing" | "找资源" | "问教材" | ...,
  "conversation_context": {
    "summary": "对话摘要（见§6）",
    "recent_turns": [
      {"role": "user", "content": "..."},
      {"role": "assistant", "content": "..."}
    ]
  },
  "escalation_context": null | {
    "from_scene": "找资源",
    "scene_judgment": "不确定是否属于问教材",
    "reason": "用户问了一个知识概念问题，但可能是对当前资源内容的追问"
  },
  "scene_registry": [ ... ]
}
```

### 4.3 系统提示词

```
## 角色

你是学科网 AI 小博士的意图路由模块。你的唯一职责是判断用户输入需要调起哪个场景，或者不需要调起。

你不负责回答用户问题。你只输出路由判断结果。

## 场景注册表

以下是当前可用的所有场景：

{{scene_registry}}

每个场景有 name（名称）、type（heavy=重场景/light=轻场景）、description（能力描述）、trigger_signals（触发信号）、core_capabilities（核心能力）、example_inputs（典型输入示例）。

## 判断规则

### 情况一：全局路由（workspace_state 为 "home" 或 "processing"）

右侧当前是场景区首页，需要从零判断用户意图。按以下优先级：

1. 用户输入包含明确的附件处理意图（批改作业、分析试卷、解析题目）→ 对应场景
2. 用户输入包含明确的生成类意图（做课件、写教案、出卷子、画导图）→ 对应场景
3. 用户输入包含明确的资源检索意图 → 找资源
4. 用户输入是知识概念问题（"X是什么""为什么Y""A和B的区别"）→ 问教材
5. 用户输入是教学方法问题（"怎么教""怎么讲""学生搞不懂"）→ 方法指导（轻场景）
6. 用户输入匹配其他轻场景的触发信号 → 对应轻场景
7. 以上都不命中 → 不调起场景，通用回答

短关键词处理：
- 纯学科知识词（如"三角函数""光合作用"），无动作词、无明确任务意图 → 默认调起问教材
- 理由：知识概览 + 后续动作是信息密度最高的首响应

### 情况二：升级仲裁（workspace_state 为具体场景名）

此时 escalation_context 不为空，包含当前场景 Agent 的初步判断和不确定原因。

判断逻辑：
1. 结合 escalation_context.reason 和 conversation_context，判断输入是否确实属于另一个场景 → 转场
2. 输入在整个场景体系里无归属（非教学、闲聊等）→ 通用回答，工作台不动
3. 仍然无法判断 → 保持当前场景处理（宁可让当前场景兜底，也不要误转场）

仲裁原则：
- 当前场景 Agent 已经判断过一次了，你是第二道判断。如果你也不确定，倾向保持当前场景。
- 误转场比漏转场的体验更差——用户突然被带到不相关的场景会困惑。

## 上下文传递规则

当判断需要调起或切换场景时，决定是否携带上下文：

- 新任务和 conversation_context 中的当前主题相关（同学科、同知识点、同教材）→ carry_context: true，提取相关字段
- 新任务和当前主题无关 → carry_context: false

可提取的上下文字段：subject（学科）、grade（学段/年级）、topic（知识点/主题）、textbook（教材版本）、difficulty（难度）、source_scene（来源场景）。

## 输出格式

严格输出以下 JSON，不输出其他任何内容：

{
  "action": "open_scene" | "switch_scene" | "stay" | "general_response",
  "target_scene": "场景名" | null,
  "scene_type": "heavy" | "light" | null,
  "confidence": 0.0-1.0,
  "basis": ["判断依据1", "判断依据2"],
  "carry_context": true | false,
  "context": {
    "subject": "数学",
    "grade": "七年级",
    "topic": "有理数",
    "textbook": "人教版·七年级·上册",
    "source_scene": "问教材"
  } | null,
  "secondary_intents": ["次要意图1"],
  "followup_suggestions": ["建议的后续动作1", "建议的后续动作2"]
}

字段说明：
- action：
  - open_scene：从首页调起场景工作台
  - switch_scene：从当前场景切换到另一个场景（仅升级仲裁时使用）
  - stay：保持当前场景处理（仅升级仲裁时使用）
  - general_response：通用回答，右侧状态不变
- target_scene：目标场景名，action 为 stay 或 general_response 时为 null
- scene_type：目标场景类型，heavy 或 light
- confidence：置信度，0.0-1.0
- basis：判断依据，用于调试和前端展示路由过程
- carry_context：是否携带上下文到目标场景
- context：传递的上下文内容，carry_context 为 false 时为 null
- secondary_intents：识别到的次要意图，用于生成后续动作建议
- followup_suggestions：推荐的后续动作文案。action 为 general_response 时，应包含可能关联的场景入口引导（如"需要我做成课件，随时说一声"）

置信度使用规则（由调用方处理，路由 Agent 只输出置信度）：
- ≥ 0.8：自动调起场景
- 0.5~0.8：左侧回答 + 引导用户确认场景方向
- < 0.5：左侧直接回答，不调起场景
```

### 4.4 路由过程可视化

路由 Agent 的 basis 字段对应前端的路由过程展示：

```
正在理解你的需求
  ✓ 理解需求
  ✓ 提取关键信息          ← basis[0]
      需求：教学创作
  ✓ 检索学科网权威库       ← 固定步骤（如有RAG环节）
      匹配三审三校精品内容作为底座
  ✓ 识别场景 97%          ← confidence + target_scene
      → 调起「出卷子」
```

当 action 为 general_response 时：

```
  ✓ 未匹配到专用工具
  → 由通用助手解答
      直接对话回答你的问题
```

## 5. 场景 Agent 边界判断模块

边界判断嵌入在每个场景 Agent 的系统提示词中，作为处理用户输入的第一步。不产生额外 LLM 调用。

### 5.1 通用边界判断提示词模板

以下模板嵌入每个场景 Agent 的系统提示词开头：

```
## 边界判断

在处理用户输入之前，你需要先判断这个输入是否在你的职责范围内。

### 你的能力范围

{{current_scene_capabilities}}

### 你的预设后续动作（可触发转场）

{{current_scene_followup_actions}}

### 其他场景的核心能力（用于识别转场目标）

{{other_scenes_summary}}

### 判断逻辑

收到用户输入后，按顺序过四关：

第一关：你的能力范围或预设后续动作能覆盖？
→ 能覆盖：直接处理。如果是预设后续动作触发的转场，在回答中执行转场并携带相关上下文。

第二关：输入明确属于另一个场景的核心能力？
→ 是：输出边界判断结果，请求转场。
判断时注意：必须是"明确属于"，不是"可能沾边"。如果只是稍微相关但你也能处理，走第一关。

第三关：输入在整个教学场景体系里都找不到归属？（非教学、闲聊、翻译等）
→ 是：用通用能力直接回答，不改变场景状态。这是临时响应，用户的下一句输入仍在你的场景上下文中。

第四关：以上都不确定。
→ 升级给路由 Agent 仲裁。输出你的初步判断和不确定原因。

重要区分：第二关和第三关的区别是输入是否有明确的场景归属。
- "三角函数是什么" → 明确属于问教材 → 第二关
- "今天天气怎么样" → 无场景归属 → 第三关

### 边界判断输出

当判断结果不是第一关（直接处理）时，输出结构化边界判断：

第二关命中：
{"boundary": "switch", "target": "问教材", "carry_context": true, "context": {"topic": "三角函数", "subject": "数学"}, "reason": "纯知识理解问题，属于问教材核心能力"}

第三关命中：
{"boundary": "general", "reason": "非教学问题，场景体系内无归属"}
（然后直接用通用能力回答）

第四关命中：
{"boundary": "escalate", "preliminary_judgment": "可能属于问教材，但也可能是对当前资源内容的追问", "reason": "用户问了概念问题，但当前正在浏览相关资源，不确定是知识追问还是资源内容追问"}
```

### 5.2 找资源场景 Agent 示例

将模板填充为找资源场景的具体内容：

```
## 边界判断

在处理用户输入之前，你需要先判断这个输入是否在你的职责范围内。

### 你的能力范围

- 资源检索：根据学科、学段、资源类型、知识点等条件搜索资源
- 搜索条件的累积和调整：换学科、调难度、换年级、缩小/扩大范围
- 资源结果的浏览、筛选、收藏、下载
- 资源详情页的内容问答：基于资源正文的 RAG 问答（总结考点、讲题等）
- 接受用户补充信息：用户补充学科、年级、难度等上下文信息

### 你的预设后续动作（可触发转场）
```

### 5.3 Function Calling 工具定义（备选方案）

作为自然语言边界判断的替代方案，可以定义 function calling 工具让模型调用。两种方式可并存——提示词中用自然语言描述判断逻辑，同时提供工具定义让模型输出结构化结果。

```json
{
  "name": "route_decision",
  "description": "当你判断用户输入不在你的能力范围内时，调用此工具输出路由决策。如果输入在你的能力范围内，不要调用此工具，直接处理。",
  "parameters": {
    "type": "object",
    "properties": {
      "boundary": {
        "type": "string",
        "enum": ["switch", "general", "escalate"],
        "description": "switch=明确属于另一个场景，general=场景体系内无归属用通用能力回答，escalate=不确定需要路由Agent仲裁"
      },
      "target": {
        "type": "string",
        "description": "转场目标场景名。boundary为switch时必填，其他情况为null"
      },
      "carry_context": {
        "type": "boolean",
        "description": "是否携带当前场景的上下文到目标场景"
      },
      "context": {
        "type": "object",
        "description": "携带的上下文内容",
        "properties": {
          "subject": {"type": "string"},
          "grade": {"type": "string"},
          "topic": {"type": "string"},
          "textbook": {"type": "string"},
          "difficulty": {"type": "string"},
          "resource_id": {"type": "string"},
          "resource_title": {"type": "string"}
        }
      },
      "reason": {
        "type": "string",
        "description": "判断理由，用于调试"
      },
      "preliminary_judgment": {
        "type": "string",
        "description": "初步判断（仅escalate时使用），告诉路由Agent你的倾向"
      }
    },
    "required": ["boundary", "reason"]
  }
}
```

使用方式：场景 Agent 收到用户输入后，如果判断不在自己能力范围内，调用 `route_decision` 工具；如果在自己能力范围内，直接回答，不调用工具。调用方根据是否调用了 `route_decision` 来决定后续流程。

**自然语言 vs Function Calling 的取舍**，建议由开发根据实际模型表现决定：

| 维度 | 自然语言输出 | Function Calling |
| --- | --- | --- |
| 输出可控性 | 需要额外解析，格式可能不稳定 | 结构化输出，格式稳定 |
| 实现复杂度 | 简单，只需提示词 | 需要定义工具、处理工具调用流程 |
| 与场景处理的耦合 | 边界判断和回答在同一次输出中 | 工具调用和回答分离，流程更清晰 |
| 调试便利性 | 判断理由在文本中，需要提取 | 判断理由在工具参数中，结构化可查 |

## 6. 对话历史摘要方案

路由 Agent 需要对话历史来判断上下文，但传全量历史 token 消耗过大。采用"摘要 + 最近原文"的方式。

### 6.1 传递给路由 Agent 的格式

```json
{
  "conversation_context": {
    "summary": "对话摘要文本",
    "recent_turns": [
      {"role": "user", "content": "最近第2轮用户输入"},
      {"role": "assistant", "content": "最近第2轮助手回答（截断至前200字）"},
      {"role": "user", "content": "最近第1轮用户输入"},
      {"role": "assistant", "content": "最近第1轮助手回答（截断至前200字）"}
    ]
  }
}
```

最近 2 轮保留原文（助手回答截断，只保留前 200 字），更早的对话压缩为摘要。

### 6.2 摘要生成方案

摘要不由路由 Agent 生成，而是由独立的摘要模块维护——每轮对话结束后增量更新。

**摘要格式（结构化，非自由文本）：**

```json
{
  "current_topic": "三角函数",
  "current_scene": "问教材",
  "subject": "数学",
  "grade": "高一",
  "textbook": "人教版·高中数学·必修一",
  "task_state": "用户已提问三角函数的定义，助手已回答并提供了知识卡片",
  "key_entities": ["三角函数", "正弦", "余弦", "单位圆"],
  "user_preferences": {
    "difficulty": "中等",
    "style": "通俗易懂"
  },
  "scene_history": ["问教材(三角函数定义)", "找资源(三角函数试卷)"],
  "turn_count": 8
}
```

**摘要更新策略：**

| 方案 | 做法 | 优缺点 |
| --- | --- | --- |
| A. 每轮 LLM 更新 | 每轮对话结束后，用轻量 LLM 调用更新摘要 | 最准确，但每轮多一次 LLM 调用 |
| B. 规则提取 + 定期 LLM | 每轮用规则提取关键字段（学科、年级等），每 N 轮用 LLM 整理一次 | 平衡成本和准确度 |
| C. 场景 Agent 附带输出 | 场景 Agent 每次回答时顺便输出摘要更新 | 零额外调用，但增加场景 Agent 输出复杂度 |

**建议采用方案 C**：在场景 Agent 的输出格式中增加一个 `context_update` 字段，每次回答时顺便更新当前主题、学科、知识点等关键字段。这样不需要额外的 LLM 调用，摘要始终保持最新。

场景 Agent 输出示例：

```json
{
  "response": "三角函数是...",
  "context_update": {
    "current_topic": "三角函数定义",
    "subject": "数学",
    "grade": "高一",
    "key_entities": ["三角函数", "正弦", "余弦", "正切"]
  }
}
```

## 7. 完整调用链路示例

### 示例 1：无工作台状态，明确意图

```
用户输入："找一份七年级数学三角函数试卷"
workspace_state: "home"

→ 规则层：匹配 (找, 试卷) → 找资源 ✓
→ 直接调起找资源工作台，不调用路由 Agent
→ 前端展示路由过程：理解需求 → 提取关键信息(资源检索/七年级数学/三角函数) → 调起找资源
```

### 示例 2：无工作台状态，短关键词

```
用户输入："三角函数"
workspace_state: "home"

→ 规则层：无动作词，未匹配 ✗
→ 路由 Agent：短关键词，纯知识词 → 问教材（confidence: 0.75）
→ 置信度 0.5~0.8，左侧回答知识概览 + 引导确认方向
→ 前端展示：理解需求 → 提取关键信息(知识概念/三角函数) → 调起问教材
```

### 示例 3：有工作台状态，场景内处理

```
用户输入："难度再高一点"
workspace_state: "找资源"

→ 规则层：未匹配 ✗
→ 找资源 Agent 边界判断：第一关命中（搜索条件累积调整）
→ 找资源 Agent 直接处理，调整难度重新搜索
```

### 示例 4：有工作台状态，明确转场

```
用户输入："三角函数是什么"
workspace_state: "找资源"

→ 规则层：未匹配 ✗
→ 找资源 Agent 边界判断：第二关命中 → 纯知识理解问题，属于问教材
→ 输出 route_decision: {boundary: "switch", target: "问教材", carry_context: true, context: {topic: "三角函数", subject: "数学"}}
→ 转场到问教材，携带上下文
```

### 示例 5：有工作台状态，场景外临时响应

```
用户输入："今天天气怎么样"
workspace_state: "找资源"

→ 规则层：未匹配 ✗
→ 找资源 Agent 边界判断：第三关命中 → 非教学，无场景归属
→ 输出 route_decision: {boundary: "general", reason: "非教学问题"}
→ 通用能力回答，找资源工作台保持不动
```

### 示例 6：有工作台状态，不确定升级

```
用户输入："这个知识点怎么讲比较好"
workspace_state: "找资源"（正在浏览三角函数相关资源）

→ 规则层：未匹配 ✗
→ 找资源 Agent 边界判断：第四关 → 不确定
  - 可能是方法指导（怎么讲 → 轻场景）
  - 也可能是对当前资源的使用建议（怎么用这份资源来讲）
→ 输出 route_decision: {boundary: "escalate", preliminary_judgment: "可能是方法指导，但也可能是对当前资源的使用建议", reason: "包含教学方法信号，但上下文中有具体资源"}
→ 升级给路由 Agent
→ 路由 Agent 结合对话摘要判断：当前正在浏览三角函数资源，"怎么讲"更可能是"怎么用这份资源来讲" → stay
→ 找资源 Agent 处理
```
