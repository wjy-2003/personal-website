## 1. 核心认知（先对齐，否则方向会错）

问教材里 **LLM 不应该凭记忆讲教材**。真正形成差异化和可信度的是学科网已有的教材库、教材目录、教材原文、用户上传内容和可追溯引用。LLM 的核心价值不是“知道教材”，而是把用户问题理解清楚、把教材依据组织清楚、把回答讲清楚。

一句话原则：**先保证回答有据可依，再追求讲得漂亮。**

问教材不是普通问答，也不是找资源或生成课件：

- 它承接的是教师围绕教材知识、学科概念、课标内容、课堂讲解对象的轻量提问；
- 它不负责查找已有课件/试卷资源，资源检索应交给找资源；
- 它不直接生成完整教学产物，教案、课件、试卷等应通过后续动作 handoff；
- 它可以把当前回答二次加工为知识卡片、讲义版、导图、练习题，但这些动作必须继承当前回答依据。

原型当前支持“不限教材直接问”“选择一本教材”“勾选多本教材综合复习/跨教材对比”“右侧教材依据/教材目录”“查看教材原文扫描页”。真实系统落地时，重点不是复刻 mock，而是把这些交互背后的数据契约和引用可信机制做实。

## 2. 系统架构分层

问教材拆成六层，职责需要分清。下面六个名字（路由层 / Agent 层 / 教材上下文层 / RAG 层 / 生成层 / 展示层）在全文统一使用：

```text
┌────────────────────────────────────────────────────┐
│ 【路由层】全局意图路由（所有场景之前）                 │ ← LLM 触点①
│   决定：这句话进不进“问教材”                           │
└────────────────────────────────────────────────────┘
                      │ 命中问教材
                      ▼
┌────────────────────────────────────────────────────┐
│ 【Agent 层】问教材对话编排                             │ ← LLM 触点②
│   解析输入 → 判断追问 → 选择上下文 → 调用 RAG/生成      │
└────────────────────────────────────────────────────┘
                      │
                      ▼
┌────────────────────────────────────────────────────┐
│ 【教材上下文层】当前问题基于什么回答                     │
│   指定教材 / 多本教材 / 上传内容 / 候选教材 / 通用知识   │
└────────────────────────────────────────────────────┘
                      │
                      ▼
┌────────────────────────────────────────────────────┐
│ 【RAG 层】教材检索与依据构建（确定性工程 + 向量检索）     │
│   知识点召回 · 章节片段召回 · 重排 · 可靠性判断 · 引用   │
└────────────────────────────────────────────────────┘
                      │
                      ▼
┌────────────────────────────────────────────────────┐
│ 【生成层】回答生成与二次加工                            │ ← LLM 触点③/④
│   动态回答结构 · 回答依据文案 · 知识卡片 · 后续动作      │
└────────────────────────────────────────────────────┘
                      │
                      ▼
┌────────────────────────────────────────────────────┐
│ 【展示层】前端交互                                      │
│   教材选择 · 教材目录 · 教材依据 · 原文查看 · handoff    │
└────────────────────────────────────────────────────┘
```

> **handoff 含义**：从问教材切换到其他教学场景，如找资源、出卷子、做课件、生成导图。用户感知应是同一位助手继续工作，而不是重新开一条孤立会话。

关键分工纪律：

- **教材依据、章节、页码、原文片段必须来自 RAG 层或教材服务，不交给 LLM 编造。**
- **上下文类型必须明确标注。** 用户已指定、系统候选、上传内容、通用知识不能混着说。
- **追问要克制。** 教师常用短关键词提问，能直接答就直接答，只有无法可靠回答时才追问一轮。
- **后续动作继承当前依据。** 知识卡片、讲义版、导图、练习题不能脱离原回答重新发散。

## 3. 实现步骤与里程碑

按推荐落地顺序排列。前序阶段是后序阶段的硬依赖。

### 阶段 0：教材数据与 RAG 底座（最难，先做）

| 产出 | 说明 | 阻塞关系 |
| --- | --- | --- |
| 教材元数据 schema | 版本、学段、学科、年级、册次、章节、页码/位置、内容类型 | 阻塞 RAG |
| 教材目录结构 | 支持右侧目录、章节定位、当前 section 状态 | 阻塞前端目录 |
| 教材正文结构化 | OCR/解析后形成可检索片段，保留页码和原文位置 | 阻塞引用 |
| 向量索引/关键词索引 | 支持知识点召回、章节片段召回、跨教材对比 | 阻塞检索 |
| 上传内容识别 | 支持图片/截图/讲义片段 OCR 或文档解析 | 阻塞截图提问 |
| 引用对象模型 | 每条引用有 source、loc、quote、page/image_url 等字段 | 阻塞依据展示 |

### 阶段 1：全局意图路由层

| 产出 | 说明 |
| --- | --- |
| 路由分类能力 | 判断用户是否进入问教材 |
| 混合意图规则 | “知识 + 资源”先问教材后挂资源入口；“知识 + 生成”转生成场景 |
| 低置信度确认 | 置信度低时轻量确认，不直接执行错误场景 |
| 场景手动切换 | 用户纠正时允许切换到问教材/找资源/生成类 |

### 阶段 2：问教材 Agent

| 产出 | 说明 |
| --- | --- |
| 输入解析能力 | 学科、学段、知识主题、问题类型、输出深度、指代关系 |
| 追问决策 | 最多一轮，补齐最小必要信息 |
| 教材上下文判断 | 指定教材 / 多本教材 / 上传内容 / 候选教材 / 通用知识 |
| RAG 调用编排 | 根据上下文决定查指定教材、查多本教材、读上传内容或降级 |
| 后续动作编排 | 知识卡片、查看相关资源、生成导图、出练习题等 |

### 阶段 3：RAG 检索与可靠性判断

| 产出 | 说明 |
| --- | --- |
| query rewrite | 将自然语言问题改写成知识点、章节、同义表达 |
| 分层召回 | 先知识点/目录定位，再章节片段召回 |
| 多本教材对比 | 多本教材分别检索，保留版本差异 |
| 片段重排 | 按主题相关性、教材范围、章节位置重排 |
| 可靠性判断 | 决定能否引用教材，是否降级为通用知识 |
| 引用清洗 | 将 v3 末尾来源编号等原始标记转成结构化 citation |

### 阶段 4：回答生成与二次加工

| 产出 | 说明 |
| --- | --- |
| 动态回答模板 | 概念解释、原因解释、对比分析、课堂讲解等 |
| 回答依据文案 | “基于/根据上传内容/可能关联/通用知识/跨教材对照” |
| 知识卡片生成 | 基于当前回答和依据二次加工 |
| 讲义版/导图/练习题衔接 | 明确留在问教材还是 handoff 到其他场景 |
| 防幻觉校验 | 回答中的教材出处必须在 citation 集合内 |

### 阶段 5：前端展示与状态管理

| 产出 | 说明 |
| --- | --- |
| 冷启动选择器 | 不限教材直接问 / 继续上次 / 选择一本 / 勾选多本 |
| 输入区 | 文本、截图/附件、教材状态、发送状态 |
| 右侧教材面板 | 教材身份栏、教材依据、教材目录 |
| 移动端底部抽屉 | 依据、目录、切换教材适配移动端 |
| 原文查看 | 引用片段可打开教材扫描页或原文位置 |
| 切换教材重答 | 切换后提示“按新教材重新回答”，不静默替换旧答案 |

### 阶段 6：灰度与评估

| 核心指标 | 含义 |
| --- | --- |
| 路由命中准确率 | 是否正确进入问教材 |
| 追问触发准确率 | 是否只在必要时追问 |
| 检索命中率 | 能否找到相关教材片段 |
| 依据覆盖率 | 回答中有明确依据展示的比例 |
| 引用准确率 | 引用片段是否真实支撑回答结论 |
| 幻觉率 | 出现无依据教材断言的比例 |
| 教材切换率 | 用户看到答案后切换教材的比例 |
| 重新回答率 | 用户因教材不匹配或回答不准触发重答 |
| 后续动作点击率 | 知识卡片、相关资源、导图、练习题等动作有效性 |
| 教研抽检通过率 | 学科专家抽查准确度 |

## 4. 数据与服务规格

### 4.1 教材元数据 schema

每个教材片段至少包含：

| 字段 | 用途 |
| --- | --- |
| textbook_id | 教材唯一 ID |
| edition | 版本，如人教版、统编版、北师大版 |
| stage | 学段，小学/初中/高中 |
| subject | 学科 |
| grade | 年级 |
| book | 册次，如必修1、七年级上册 |
| chapter_id / chapter_name | 章节定位 |
| section_id / section_name | 小节定位 |
| page_no / position | 页码或原文位置 |

### 4.4 textbook-chat-v2/v3 接入建议

现有教材百科能力可分工使用：

| 能力 | 适合承担 | 使用位置 |
| --- | --- | --- |
| textbook-chat-v3 | 实时流式问答，用户直接提问 → 检索知识库 → 大模型基于教材内容生成，答案末尾带来源编号 | 问教材主问答链路 |
| textbook-chat-v2 | 对已有上游内容做教材化增强，返回相关知识点 + 教材章节内容列表 | 回答区知识点标签、章节依据卡片、知识卡片前置材料 |

接入纪律：

- v3 的原始来源编号不能直接暴露给用户，需要解析成结构化 citation；
- v2 返回的章节内容可作为右侧依据补充，但不能替代主回答的引用校验；
- 如果 v3 检索结果可靠性不足，应降级为通用知识回答，而不是强行引用；
- 如果用户切换教材，必须重新调用对应教材范围的检索/问答，不复用旧教材答案。

## 5. LLM 触点与系统提示词

问教材不应该用一个大 prompt 包圆。建议拆成五个触点：

| 触点 | 所在层 | 职责 | 形态 |
| --- | --- | --- | --- |
| ① 全局路由 | 路由层 | 判断进不进问教材 | 分类 prompt 或轻量模型 |
| ② 问教材 Agent | Agent 层 | 解析、追问、上下文判断、工具编排 | system prompt + 工具调用 |
| ③ 可靠性评估 | RAG 层/生成前 | 判断能否引用教材 | 小 prompt 或规则 + 模型 |
| ④ 回答生成 | 生成层 | 基于依据生成动态结构回答 | system prompt |
| ⑤ 二次加工 | 生成层 | 知识卡片、讲义版、后续动作 | 独立 prompt |

### 5.0 问教材问题类型体系

问题类型要尽量覆盖教师真实问法，但也不能无限细分。推荐采用 **14 个业务类型 + 3 个兜底类型**。业务类型用于选择回答结构和卡片结构；兜底类型用于避免模型硬分类。

| 类型 | 典型问题 | 回答结构 |
| --- | --- | --- |
| 概念解释型 | 什么是电磁感应？什么是实数？ | 一句话定义 → 核心要点 → 教材位置/出处 → 示例 → 易错点 |
| 原理机制型 | 光合作用的过程是什么？这个公式怎么来的？ | 核心原理 → 过程/推导链条 → 关键条件 → 常见误区 |
| 原因解释型 | 为什么要检测子代放射性？为什么教材这样安排？ | 直接结论 → 原因链条 → 情境还原 → 常见误区 |
| 对比辨析型 | 光反应和暗反应有什么区别？比喻和拟人怎么区分？ | 总体区别 → 对比维度 → 易混点 → 记忆方法 |
| 易错辨析型 | 学生哪里容易错？这个点容易和什么混？ | 易错点 → 错因分析 → 正确理解 → 纠错方法 |
| 归纳总结型 | 这一节重点有哪些？环境描写作用有哪些？ | 总括结论 → 分点归纳 → 使用场景 → 表达示例 |
| 知识脉络型 | 这一章知识怎么串起来？前后知识有什么关系？ | 上位主题 → 知识结构 → 前后关联 → 学习路径 |
| 教材定位型 | 这个知识点在哪一章？前面学过什么？ | 相关章节 → 出现位置 → 前后知识关系 → 建议阅读路径 |
| 教材解读型 | 这段教材想让学生理解什么？这页怎么读？ | 教材内容概括 → 编排意图 → 学习目标 → 理解抓手 |
| 课堂讲解型 | 这页怎么讲？这个概念怎么讲清楚？ | 讲解目标 → 学生易卡点 → 讲解步骤 → 板书关键词 |
| 教学设计启发型 | 这里怎么导入？怎么设计活动？ | 教学目标 → 导入/活动建议 → 组织方式 → 注意事项 |
| 应用理解型 | 这个知识点生活中怎么用？在物理里怎么用？ | 应用场景 → 对应知识点 → 典型例子 → 易错提醒 |
| 考法分析型 | 中考/高考怎么考？常见题型有哪些？ | 考查方向 → 常见题型 → 解题抓手 → 备考提醒 |
| 题目知识点定位型 | 这道题考哪个知识点？对应教材哪里？ | 题目识别 → 对应知识点 → 教材位置 → 考查方式 → 易错提醒 |

兜底类型：

| 兜底类型 | 使用条件 | 处理方式 |
| --- | --- | --- |
| 泛知识问答型 | 属于学科知识，但无法判断具体业务类型 | 直接回答 → 核心要点 → 与教材/章节的可能关联 → 可继续追问方向 |
| 教材相关未分类型 | 明显依赖教材内容，但不属于上述类型 | 先说明依据状态 → 基于已有信息回答 → 标注不确定性 → 引导选择教材或补充信息 |
| 需要澄清型 | 缺少主题、无指代对象、图片识别不清 | 最多追问一轮，给结构化选项并保留自由输入 |

分类原则：

- 能归入明确业务类型时，不使用兜底类型；
- “题目知识点定位型”和“题目解析”不同：用户问考什么知识点/对应教材哪里，留在问教材；用户问答案/解析/怎么做，转题目解析；
- “教学设计启发型”和“写教案”不同：轻量导入、活动建议留在问教材；完整教案生成转写教案；
- “考法分析型”和“出卷子”不同：分析怎么考留在问教材；要求生成试题/试卷转出卷子；
- 兜底类型是安全网，不是偷懒入口。分类不确定但可直接回答时，用泛知识问答型；依据状态不清时，用教材相关未分类型；最小信息不够时，才用需要澄清型。

### 5.1 全局路由提示词（触点①）

```text
判断用户输入应进入哪个教学场景，只输出 JSON，不输出解释文字。

可选场景：
- 找资源：用户要找、下载、查看已有资源、课件、试卷、教案、讲义等。
- 做课件：用户明确要生成 PPT、课件页、互动课件。
- 写教案：用户明确要生成教学设计、教案、教学过程。
- 出卷子：用户明确要出题、组卷、生成测试卷。
- 题目解析：用户提供题干、选项、题目截图，并询问答案、解析、怎么做。
- 问教材：用户围绕学科知识、教材内容、概念、定理、原因、区别、课堂讲解对象提问。
- 方法指导：用户询问怎么教、怎么导入、怎么引导学生理解。
- 通用问答：非教学或无法识别。

优先级：
明确文件/题目处理 > 明确生成 > 找资源 > 问教材 > 方法指导 > 通用。

特殊规则：
1. “三角函数”“光合作用”这类短知识点，默认进入问教材。
2. “X 是什么/为什么/有什么区别/怎么理解/这页怎么讲”进入问教材。
3. “找 X 课件/下载 X 试卷/有没有 X 资源”进入找资源。
4. “生成 X PPT/写 X 教案/出 X 试卷”进入对应生成场景。
5. “知识 + 资源”混合，如“X 有哪些重点？有没有课件？”先进入问教材，并把“查看相关资源”作为后续动作。
6. 置信度低时返回 need_confirm=true，不要直接执行错误场景。

输出 JSON：
{
  "main_scene": "",
  "confidence": 0,
  "secondary_intents": [],
  "evidence": [],
  "need_confirm": false,
  "suggested_actions": []
}
```

> 上线前需调整：用真实用户输入跑样本，重点复核“题目解析 vs 问教材”“找资源 vs 问教材”“方法指导 vs 问教材”的误判。

### 5.2 问教材 Agent 系统提示词（触点②，主方案）

```text

- 你不能凭空声称“教材中指出”“课本上说”。只有工具返回了可追溯教材片段时，才能引用教材依据。

- 用户本轮输入
- 对话历史
- 当前教材状态：不限教材 / 已选一本教材 / 已选多本教材 / 继续上次教材
- 当前教材目录位置（如有）
- 上传附件识别结果（如有）
- 用户登录态与历史教材偏好（如有）

# 工作流程
1. 解析用户输入：
   识别学科、学段/年级、知识主题、问题类型、输出深度、是否有指代、是否有上传内容。

2. 判断是否需要追问：
   - 主题明确、学科可稳定推断时，直接回答。
   - 主题缺失，如“帮我讲一下”，追问学科和知识主题。
   - 无上下文指代，如“这个怎么证明”但无附件/上文，追问上传截图或补充文本。
   - 用户要求按某版教材解释但未选具体教材，追问或打开教材选择。
   - 图片识别不清，要求重新上传或补充文字。
   - 最多追问一轮；用户不补充时，用现有信息给通用概览或引导。

3. 判断教材上下文：
   - 有上传内容：优先基于上传内容，已选教材只作为补充。
   - 已选一本教材：基于指定教材检索。
   - 已选多本教材：多本教材分别检索，适合跨教材对比。
   - 不限教材但能识别学科/学段：候选教材检索，不能断言具体版本。
   - 无可靠教材上下文：通用学科知识回答，并提示可选择教材获得更贴合课本的解释。

4. 调用教材检索/问答工具：
   根据上下文调用 textbook_retrieve 或 textbook_chat。不要自己生成教材出处。

5. 生成回答：
   - 先给直接答案。
   - 根据问题类型选择结构。
   - 明确回答依据类型。
   - 给出 2-4 个后续教学动作。

6. 识别 handoff：
   - “找相关课件/试卷/资源” → 找资源。
   - “出几道题/生成练习” → 出卷子。
   - “生成导图” → 思维导图。
   - “做课件/写教案” → 对应生成场景。
   handoff 时携带当前知识主题、学科、学段、教材依据。

# 语气
简洁、专业，像一个懂教学的同事。先帮教师解决问题，再给可继续操作的入口。
```

| 泛知识问答型 | 直接回答 → 核心要点 → 与教材/章节的可能关联 → 可继续追问方向 | 通用知识卡 | 标题 → 直接回答 → 核心要点 → 延伸方向 |
| 教材相关未分类型 | 先说明依据状态 → 基于已有信息回答 → 标注不确定性 → 引导选择教材或补充信息 | 教材依据卡 | 当前依据状态 → 已知信息 → 不确定点 → 建议补充 |
| 需要澄清型 | 最多追问一轮，给结构化选项并保留自由输入 | 不生成卡片 | 先完成澄清，再根据新问题类型生成卡片 |

```text
你是问教材的知识卡片生成器。请把当前回答整理成适合课堂展示、学生复习或课件嵌入的知识卡片。

要求：
1. 只能基于当前回答和已有依据生成，不重新引入未经验证的新知识。
2. 每张卡片只承载一个知识主题。
3. 默认 16:9 横版内容结构。
4. 不超过 5 个核心要点。
5. 根据问题类型选择对应卡片类型：
   - 概念卡：标题 → 核心定义 → 关键要点 → 示例 → 易错提醒
   - 原理机制卡：标题 → 核心原理 → 过程链条/推导步骤 → 关键条件 → 易错提醒
   - 原因链条卡：标题 → 直接结论 → 原因链条 → 情境/实验还原 → 易错提醒
   - 对比卡：对比对象 → 核心区别 → 对比表 → 易混点 → 记忆方法
   - 易错辨析卡：易错点 → 错因分析 → 正确理解 → 纠错方法
   - 归纳卡：标题 → 总括结论 → 分点归纳 → 使用场景 → 表达示例
   - 知识脉络卡：上位主题 → 结构图式 → 前后关联 → 学习路径
   - 教材定位卡：知识点 → 教材位置 → 前后关联 → 阅读路径
   - 教材解读卡：教材内容 → 编排意图 → 学习目标 → 理解抓手
   - 讲解卡：讲解目标 → 学生易卡点 → 讲解步骤 → 板书关键词
   - 教学启发卡：教学目标 → 导入/活动建议 → 组织方式 → 注意事项
   - 应用卡：应用场景 → 对应知识点 → 典型例子 → 易错提醒
   - 考法分析卡：考查方向 → 常见题型 → 解题抓手 → 备考提醒
   - 题目定位卡：题目关键信息 → 对应知识点 → 教材位置 → 考查方式 → 易错提醒
   - 通用知识卡：标题 → 直接回答 → 核心要点 → 延伸方向
   - 教材依据卡：当前依据状态 → 已知信息 → 不确定点 → 建议补充
6. 如果问题类型是“需要澄清型”，不要生成卡片，返回 need_clarification=true。
7. 卡片底部保留来源说明。

输入：
{question_type}
{answer_markdown}
{basis}
{citations}

输出 JSON：
{
  "card_type": "",
  "need_clarification": false,
  "title": "",
  "slides": [
    {
      "title": "",
      "sections": []
    }
  ],
  "source_note": ""
}
```

## 6. 典型链路示例

### 6.1 不限教材直接问

```text
用户：三角函数
→ 路由：问教材
→ 解析：数学 / 高中可能性高 / 主题=三角函数 / 概念解释型
→ 上下文：无指定教材，候选教材或通用知识
→ RAG：可查候选高中数学必修相关章节
→ 回答：给概览解释
→ 依据：可能关联：高中数学 · 必修一。如需按具体版本讲解，请选择教材
→ 动作：展开解释 / 生成知识卡片 / 查看相关资源 / 出几道练习题
```

### 6.2 已指定教材提问

```text
当前教材：人教版 · 高中生物 · 必修1
用户：光反应和暗反应有什么区别？
→ 路由：问教材
→ 解析：生物 / 高中 / 对比辨析型
→ 上下文：指定教材
→ RAG：检索指定教材第5章第4节相关片段
→ 回答：总体区别 + 对比维度 + 易混点
→ 依据：基于：人教版 · 高中生物 · 必修1 · 第5章第4节
→ 右侧：展示 2-4 处教材原文引用，可查看扫描页
```

### 6.3 上传教材页提问

```text
用户上传教材页截图，并问：这页怎么讲？
→ 路由：问教材
→ OCR：识别上传内容
→ 解析：课堂讲解型
→ 上下文：上传内容优先
→ RAG：基于上传内容，必要时补充检索已选教材
→ 回答：讲解目标 + 学生易卡点 + 讲解步骤 + 板书关键词
→ 依据：根据你上传的教材页整理
```

### 6.4 多本教材跨教材对比

```text
用户选择：人教版七上数学、人教版八上数学、人教版九上数学
用户：一次函数在哪些教材里出现过？
→ 路由：问教材
→ 解析：数学 / 初中 / 跨教材定位
→ 上下文：多本教材
→ RAG：多本教材分别检索
→ 回答：分版本/册次说明出现位置和内容差异
→ 依据：已对照 3 本教材内容，分别标注出处
```

### 6.5 切换教材后重新回答

```text
用户看完通用回答后选择：北师大版 · 七年级上册
→ 前端更新教材状态
→ 系统提示：可按新教材重新回答
→ 用户点击重答
→ 重新进入指定教材 RAG
→ 新答案替换为基于北师大版的回答，但旧答案历史保留
```

## 7. 异常与降级策略

| 异常 | 触发条件 | 处理 |
| --- | --- | --- |
| 未登录 | 登录态不可用 | 不影响通用问教材；记忆、继续上次、个性化可能不可用 |
| 超出次数限制 | 教材百科接口达上限 | 提示今日次数已用完，可稍后或明日再试 |
| 图片识别不清 | OCR 置信度低 | 请求重新上传或补充文字，不编造 |
| 知识库无匹配 | 检索不到可靠片段 | 降级通用知识回答并标注 |
| 教材版本差异 | 版本影响答案 | 先答通用/候选，再引导选择具体教材 |
| 上传内容与已选教材冲突 | 上传页与当前教材不一致 | 以上传内容为当前上下文，并提示可能存在差异 |
| 流式生成中断 | v3 输出失败 | 提供重试 |
| 来源编号未解析 | 出现原始 `####0,2` 等 | 前端隐藏原始标记，后端解析为 citation |
| 引用不支撑结论 | 可靠性评估低 | 删除引用或降级为通用回答 |
| 用户明确要找资源 | “有没有课件/下载试卷” | handoff 到找资源 |
| 用户明确要生成产物 | “做 PPT/写教案/出卷子” | handoff 到对应生成场景 |

### 9.1 产品验收

- [ ] 首页和工作台均能进入问教材；
- [ ] 支持不限教材直接问；
- [ ] 支持选择一本教材后提问；
- [ ] 支持多本教材对比；
- [ ] 支持上传教材页/截图后提问；
- [ ] 回答下方展示依据类型；
- [ ] 右侧能查看教材依据；
- [ ] 切换教材后能重新回答；
- [ ] 知识卡片继承原回答依据；
- [ ] 后续动作能正确 handoff。

### 9.2 技术验收

- [ ] 教材 citation 不由 LLM 编造；
- [ ] 通用知识回答不会显示教材出处；
- [ ] 候选教材不会被写成用户已指定；
- [ ] v3 原始来源编号不会直接暴露；
- [ ] OCR 识别不清时不编造；
- [ ] 检索无结果时能降级；
- [ ] 回答中引用编号都能在 citations 中找到；
- [ ] 切换教材后重新检索而不是复用旧答案；
- [ ] 多本教材检索结果能按版本隔离；
- [ ] 日志保留 question、parse_result、context_type、retrieval_id、citations、answer_id。

### 9.3 教研抽检

建议灰度初期优先抽检：

- 高中数学：函数、三角函数、导数、向量；
- 高中物理：牛顿定律、电磁感应、安培力、机械能；
- 高中生物：光合作用、遗传规律、生态系统；
- 初中语文：文言文、小说环境描写、说明方法；
- 初中数学：一次函数、相似三角形、圆。

每类抽检至少看：

- 回答是否准确；
- 讲解深度是否适合教师；
- 引用是否真实支撑结论；
- 是否错误绑定教材版本；
- 后续动作是否自然。

## 10. 最小可行版本（MVP）建议

如果要尽快上线，不建议一开始做全量能力。推荐 MVP 范围：

1. 支持不限教材直接问；
2. 支持选择一本教材；
3. 支持指定教材 RAG 回答；
4. 支持回答依据展示；
5. 支持右侧引用卡片；
6. 支持切换教材后重新回答；
7. 支持“生成知识卡片”和“查看相关资源”两个后续动作；
8. 暂缓多本教材综合、复杂上传文件、讲义版生成。

MVP 不可妥协项：

- 不能编造教材出处；
- 不能把通用回答伪装成教材回答；
- 不能让来源编号裸露给用户；
- 不能图片识别不清还继续猜；
- 不能切换教材后静默改变旧答案。

## 12. 关键原则回顾

- **场景与输出形态分离**：问教材是知识解释场景，长回答/讲义版只是输出形态。
- **依据透明**：每次回答都要说明基于什么，不让用户误会。
- **不确定性透明**：候选教材、通用知识、识别不清都要明说。
- **追问克制**：最多一轮，能答先答。
- **引用可追溯**：教材依据必须能回链到教材原文。
- **后续动作不断线**：问教材回答完成后，自然衔接资源、导图、练习、卡片。
- **知识卡片不重新发散**：它是当前回答的二次加工，不是新一轮无依据生成。
