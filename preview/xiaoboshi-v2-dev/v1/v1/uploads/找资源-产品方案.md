# 找资源场景产品方案

**创建日期：** 2026-07-01
**状态：** 产品方案基线
**定位：** 补齐找资源在战略层的产品方案——场景定位从"我们认为"升级为"数据证明"，明确产品目标、范围边界与关键待解决问题。业务流程、前端交互规格分别由《找资源场景业务流程》《找资源前端交互PRD》承担，不在本文重复。
**数据来源：** 2026年5月用户对话分析全量数据（27,335 条首轮问题，清洗后）
**关联文档：** 《找资源场景业务流程》《找资源前端交互PRD》《资源详情页-问题列表交互设计》

## 1. 场景定位

找资源是小博士的「已有资源检索」场景，对应学科网作为资源聚合平台的底座能力。核心诉求：从学科网已有成品资源中，快速找到贴合班级学情的文档、视频、成套专辑。

与问教材的边界（详见《找资源场景业务流程》§1）：找资源给「已有成品」，问教材给「知识理解」；两者前后衔接，不互斥。

## 2. 数据支撑

### 2.1 体量与地位

找资源是 2026 年 5 月全场景中**占比最高的单一大类**：

| 指标 | 数值 |
| --- | --- |
| 月度首轮问题量 | 7,838 条 |
| 占全量首轮问题比例 | 28.7%（全场景第一） |
| 登录用户占比 | 6,307 / 7,838 = **80.5%** |
| 未登录用户占比 | 1,531 / 7,838 = 19.5% |

登录占比 80.5%，明显高于学科知识问答（63%）等其他类别，说明找资源是教师这一核心用户群最高频、最稳定的诉求，产品投入的确定性回报高。

### 2.2 内部构成

| 子类 | 数量 | 占比 |
| --- | --- | --- |
| 查找讲义/知识点/复习资料 | 3,454 | 44.1% |
| 查找试卷/真题/考卷 | 1,751 | 22.3% |
| 查找教案/教学设计 | 1,662 | 21.2% |
| 查找课件/PPT | 971 | 12.4% |

讲义/知识点查找是最大子类，比试卷查找多出近一倍。

### 2.3 查找精准度

| 子类 | 精准查找（含地区/版本/年份） | 模糊查找 |
| --- | --- | --- |
| 查找试卷 | 62% | 38% |
| 查找教案 | 43% | 57% |
| 查找讲义 | 26% | 74% |
| 查找课件 | 13% | 87% |

**关键发现**：

- 试卷查找最精准（62% 含地区+年份），用户对试卷有明确的来源定位诉求，77% 含考试词、50% 含地区词。
- 课件查找精准化程度最低（仅 13%），但体量排第三——用户想找课件，但往往说不清要什么版本/地区。
- 讲义查找体量最大（44.1%）但最模糊（74%），很大一部分用户可能分不清"查找"和"生成"的边界。

这组数据直接支撑《找资源场景业务流程》§5.2 已实现的追问补全机制的必要性，也指向 §6 待解决问题里的引导优先级。

## 3. 产品目标

| 目标 | 说明 | 关联指标 |
| --- | --- | --- |
| 提升精准命中率 | 尤其是课件、讲义这两类模糊查找占比最高的子类 | 精准查找占比（当前课件 13%、讲义 26%） |
| 巩固登录心智 | 找资源已是登录用户最高频诉求之一，强化"登录后检索更准"的认知 | 登录占比（当前 80.5%） |
| 打通检索与生成 | 资源不合适时无缝流转到出卷子/写教案/做课件，不让教师空手而归 | 跨场景流转率（待埋点） |
| 区分"查找"与"生成"心智 | 讲义类需求里存在大量用户实际想要"生成"却走了"查找"入口的情况 | 待通过埋点/访谈验证 |

## 4. 范围与非目标

**范围内：**

- 学科网资源库已有成品资源（文档/视频/专辑三类形态）的检索、预览、收藏、下载
- 检索意图解析、追问补全、多源排序（我的内容 > 资源篮 > 学科网）
- 资源详情页的追问能力（问小博士）
- 资源不合适时到生成类场景（出卷子/写教案/做课件）的跨场景流转

**非目标：**

- 不做"AI 生成新资源"——这是出卷子/做课件/写教案等场景的职责，找资源只负责"已有资源"检索，需要生成时通过跨场景流转交给对应场景
- 不做资源上传/众创功能——找资源是检索入口，不是内容生产入口
- 不做资源篮的复杂管理（移动到文件夹、分享等）——按《首页交互PRD》的决策，这类功能留在学科网主站，小博士资源篮只做查看/下载/移除

## 5. 关键待解决问题

### 5.1 课件查找的前置引导（P0）

课件查找模糊度最高（87%），体量排第三（12.4%）。用户表达往往只有主题词，缺版本/地区。当前追问补全机制（`ClarifyPopover`）已经能在信息不足时弹出引导，但目前触发依据是"最小必要字段是否缺失"，对课件类是否需要更主动地前置引导（例如冷启动阶段就提示"先选学科/年级再搜索"），需要产品验证。

### 5.2 讲义查找的"查找 vs 生成"心智混淆（P0）

讲义/知识点查找体量最大（44.1%）且最模糊（74%），5 月数据分析报告推断这类需求里很大一部分用户分不清"查找现成的"和"让 AI 生成"。这不是纯交互问题，需要产品判断：入口文案、冷启动引导、结果为空时的兜底话术，要不要更早、更明确地帮用户做这个区分。

### 5.3 找资源入口的精准筛选引导（P1）

来自 5 月数据分析报告的建议：查找课件（87%模糊）和讲义（74%模糊）时，弹出「学科 + 年级 + 版本」引导选择器，减少无效结果。这与追问补全机制（`ClarifyPopover`）的能力有重叠，需要明确二者关系——是同一套机制的不同触发时机，还是两套独立机制。

### 5.4 跨场景流转的效果未验证

《找资源场景业务流程》§5.6 已定义流转路径（出卷子/写教案/做课件），但目前没有埋点数据验证这条链路的实际使用率和转化效果，无法判断这个设计假设是否成立。
