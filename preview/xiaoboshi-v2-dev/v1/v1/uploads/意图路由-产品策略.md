## 1. 策略目标

意图路由负责在用户输入后，判断是否需要调起某个场景工作台、调起哪个、以及怎么传递上下文。

路由目标有三个：

1. 当用户意图明确时，自动调起对应场景工作台，减少手动选择负担；
2. 当意图不明确或涉及多个场景时，先在对话中回答，同时引导用户可选的场景方向；
3. 当输入不需要任何场景工作台时，直接在对话中回答，不做多余动作。

## 2. 产品架构：对话层与场景层

小博士的产品架构分为两层：

| 层级 | 承载位置 | 职责 | 状态特征 |
| --- | --- | --- | --- |
| 对话层 | 左侧对话面板 | 始终通用的 AI 助手，接受任何输入，给出回答 | 始终存在，不绑定任何场景 |
| 场景层 | 右侧工作台 | 承载特定教学任务的专业工作区（找资源、出卷子、问教材等） | 按需调起，可手动切换，可为空 |

核心行为规则：

- **用户随时可以说任何话，都能得到回应。** 不存在"你在找资源场景里，只能问找资源的问题"这种锁定。
- **路由识别到需要某个场景时，自动调起对应工作台。** 用户不需要手动选场景才能开始任务。
- **进入场景后，对话和工作台各司其职。** 对话负责沟通（提问、回答、确认意图），工作台负责需要结构化交互的操作（编辑大纲、浏览资源列表、调整试卷等）。两者协同推进任务。

### 2.1 重场景与轻场景

场景按交互复杂度分为两类：

| 类型 | 右侧工作台 | 典型场景 | 特征 |
| --- | --- | --- | --- |
| 重场景 | 有专用 tab + 预设交互 UI | 找资源、问教材、出卷子、做课件、写教案、画导图、改作业 | 工作台有定制化界面（资源列表、大纲编辑器、教材面板、思维导图编辑器等），场景间通过顶部 tab 切换 |
| 轻场景 | 无专用 tab，使用通用产出面板 | 方法指导、写作文辅导、实验指导等 | 对话驱动为主，工作台根据产出物类型动态展示（文档→文档编辑/下载等） |

轻场景的工作台行为：

- **对话过程中（产出物未生成时）**：右侧展示轻量过程态，如"正在帮你写作文…"，让用户知道助手正在做什么。
- **产出物生成后**：右侧通用产出面板展示结果，支持编辑、下载等操作。
- **退出方式**：不需要手动退出。用户发起新任务时自动切换，或连续无关对话后自动回首页（见 §9.5）。

轻场景的扩展成本低——新增一个轻场景只需要加对应的 prompt 策略和产出物类型映射，不需要开发专用工作台界面。

### 2.2 助手状态标识

左上角始终表达助手状态，不表达用户所在场景：

| 右侧工作台状态 | 左上角展示 | 含义 |
| --- | --- | --- |
| 无工作台 / 场景选择首页 | 有问必答 · 全程陪伴 | 助手待命，随时可问 |
| 重场景已打开（如找资源） | 正在陪你 · 找资源 | 助手正在帮你做某件事 |
| 轻场景进行中（如写作文） | 正在陪你 · 写作文 | 同上，轻场景和重场景对用户感知一致 |

"正在陪你"的主语是助手，传递的是"我正在帮你做这件事"，不是"你被锁定在这个场景里"。左侧输入框 placeholder 始终为通用文案（如"问我任何教学问题，或描述你想创作的内容"），强化对话层的通用性。

轻场景和重场景在左上角的展示方式一致，用户不需要区分两者的差异。

### 2.3 手动切换场景

用户可随时通过右侧顶部 tab 栏手动切换工作台。手动切换时：

- 对话中插入系统提示："已切换到「出卷子」"；
- 左上角助手状态更新；
- 左侧对话线索不中断。

## 3. 路由判断框架

路由判断分两种状态：**无工作台状态**（右侧为空或场景选择首页）和**有工作台状态**（右侧已打开某个场景工作台）。

### 3.1 无工作台状态：全局路由

用户在首页或通用入口输入时，右侧没有已打开的工作台，需要从零判断。

```
用户输入
  │
  ├─ 识别到需要某个场景工作台的产出？（置信度高）
  │   └─ 左侧回答 + 右侧自动调起对应工作台
  │
  ├─ 不确定需要哪个工作台？
  │   └─ 左侧先回答 + 引导用户可选的场景方向
  │
  └─ 不需要任何工作台？（纯对话就能解决）
      └─ 左侧直接回答，右侧不动
```

全局路由的场景优先级见 §5。

**短关键词处理：** 如"三角函数""光合作用"这类短关键词，在无工作台状态下默认调起问教材工作台，给概览型知识回答，底部挂后续动作（查看相关资源、生成知识卡片、出几道练习题等），让用户自己选择深入方向。

理由：知识概览 + 后续动作是信息密度最高的首响应；教师输入短关键词时，最常见的意图是快速了解知识点，其他意图可通过后续动作覆盖。

### 3.2 有工作台状态：在场判断

用户在某个场景工作台已打开时输入，判断逻辑按顺序过四关：

```
用户输入
  │
  ├─ 第一关：当前场景的能力范围或预设后续动作能覆盖？
  │   └─ 是 → 当前场景处理（含场景内发起的转场，自然带上下文）
  │
  ├─ 第二关：输入明确属于另一个场景的核心能力？
  │   └─ 是 → 转场到目标场景，直接按该场景逻辑回答
  │
  ├─ 第三关：输入在整个场景体系里都找不到归属？
  │   └─ 是 → 通用能力直接回答，右侧工作台不动
  │
  └─ 第四关：以上都不是 → 当前场景处理
```

#### 第一关：当前场景的预设路径

每个场景定义了自己的能力范围和后续动作列表。用户输入如果落在这个范围内——不管是直接回答还是触发转场——由当前场景处理。

例如：问教材定义了"查看相关资源""出几道练习题""生成知识卡片"等后续动作。用户在问教材里说"有没有相关课件"或"出几道题练练"，虽然涉及其他场景的能力，但问教材已经预设了这条路径，上下文传递方式明确。

第一关过滤掉大多数情况。

#### 第二关：明确属于另一个场景

输入明确属于另一个场景的核心能力范围，且当前场景没有预设路径覆盖。判断依据包括但不限于：

- **动作词 + 对象词组合**：找/下载 + 试卷/课件 → 找资源；生成/做/写 + 课件/教案 → 生成类；出/组 + 卷子/题 → 出卷子。
- **问题类型**：纯知识理解问题（"X 是什么""为什么 Y"）→ 问教材；完整题目求解 → 题目解析。

命中后，直接转场到目标场景并按该场景逻辑回答，不需要用户确认。

#### 第三关：场景外临时响应

输入在整个教学场景体系里都找不到归属——没有明确的场景意图，也不属于当前场景的能力范围。典型如"今天天气怎么样""帮我翻译一句英语""中国有多少个省"。

处理方式：通用能力直接回答，右侧工作台保持不动，不改变场景状态。用户的下一句输入仍然在当前工作台的上下文中。

**关键区分：场景外临时响应 vs 第二关转场。** 区别在于输入是否有明确的场景归属。"今天天气怎么样"在教学场景体系里没有归属 → 临时响应。"三角函数是什么"在找资源工作台下，虽然也不是找资源的能力，但它明确属于问教材的核心能力 → 第二关命中，转场到问教材。

判断标准不是"当前场景能不能勉强回答"，而是"这个输入是否明确属于某个场景的核心能力"。有明确归属就转场，没有归属才临时响应。

## 4. 路由输入信号

意图路由不应只看关键词，而要综合多种信号。

| 信号类型 | 示例 | 用途 |
| --- | --- | --- |
| 动作词 | 找、下载、生成、写、出、讲、解释、分析、批改 | 判断用户要完成什么任务 |
| 学科/知识词 | 三角函数、光合作用、法拉第电磁感应定律 | 判断是否属于学科知识任务 |
| 资源词 | 试卷、课件、教案、讲义、答案、PPT | 判断是否是资源检索或成品生成 |
| 题目结构 | 题干、选项、答案、解析、图片题 | 判断是否进入题目解析 |
| 教材上下文 | 已选教材、上传教材页、历史教材偏好 | 判断是否进入问教材 |
| 附件类型 | 教材截图、试卷 PDF、作文图片、成绩表 | 辅助判断场景 |
| 对话历史 | 上一轮正在问某知识点或找某类资源 | 保持对话连续性（第一关判断的依据） |
| 当前工作台状态 | 右侧已打开找资源 / 问教材 / 无工作台 | 决定走全局路由还是在场判断 |

## 5. 场景优先级与判断规则

### 5.1 全局路由场景优先级

当无工作台状态下需要从零判断时，按任务明确度排序：

1. 明确文件/附件处理场景：作文批改、试卷分析、题目解析、成绩分析；
2. 明确生成类场景：做课件、写教案、出卷子、生成讲义；
3. 明确资源检索场景：找资源、找试卷、找课件、下载文档；
4. 问教材：知识概念、定理、原因、区别、教材内容理解；
5. 方法指导：怎么讲、怎么导入、怎么帮助学生理解；
6. 通用问答：无法命中教学场景或明显非教学意图。

优先级不是绝对规则。若用户表达非常明确，应以用户显式意图为准。

### 5.2 典型场景判断规则

| 场景 | 命中条件 | 典型输入 |
| --- | --- | --- |
| 找资源 | 含找、下载、有没有、资源、试卷、课件等资源检索意图 | "找一份三角函数试卷" |
| 做课件 | 明确要求生成课件、PPT、课件页 | "生成一份光合作用课件" |
| 写教案 | 明确要求教学设计、教案、教学过程 | "写一份《荷塘月色》教案" |
| 出卷子 | 明确要求出题、组卷、单元测试 | "出一份三角函数单元测试卷" |
| 问教材 | 问概念、定理、原因、区别、教材内容理解 | "三角函数是什么""这页怎么讲" |
| 方法指导 | 询问教师怎么教、怎么导入、怎么引导学生 | "三角函数学生老记混，怎么教" |
| 题目解析 | 粘贴完整题干/选项或上传题目截图并问答案/解析 | "这道题选什么，为什么" |
| 改作业 | 上传作业图片并要求批改、讲评 | "帮我批改这份作业" |
| 画导图 | 明确要求知识结构可视化、思维导图 | "画一张三角函数的知识导图" |
| 通用问答 | 非教学、闲聊、无法判断 | "今天天气怎么样" |

## 6. 场景转场规则

### 6.1 转场时的上下文传递

场景转场时，是否传递上下文取决于**新任务和当前对话主题是否相关**：

| 转场情况 | 上下文处理 | 举例 |
| --- | --- | --- |
| 新任务和当前主题相关 | 带上下文（学科、知识点、教材、难度等） | 问教材聊三角函数 → "找一份三角函数试卷" → 找资源知道用户关心三角函数、高一数学 |
| 新任务和当前主题无关 | 不带上下文，新场景从零开始 | 问教材聊三角函数 → "找一份英语试卷" → 找资源只知道"英语试卷" |

### 6.2 转场的用户感知

所有转场对用户的感知是一致的：

- 右侧工作台切换到目标场景；
- 左上角助手状态更新；
- 左侧对话线索不中断；
- 助手直接按目标场景逻辑回答，不需要用户额外确认。

不区分"handoff"和"切场景"两种概念——从用户视角来看，都是"助手帮我做了另一件事，右侧工作台跟着变了"。

### 6.3 在场判断的完整示例

| 当前工作台 | 用户输入 | 判断 | 结果 |
| --- | --- | --- | --- |
| 问教材（正在聊三角函数） | "有没有相关课件" | 第一关：问教材预设了"查看相关资源" | 场景内转场到找资源，带三角函数上下文 |
| 问教材（正在聊三角函数） | "找一份三角函数试卷" | 第一关：问教材预设了"查看相关资源"，主题一致 | 场景内转场到找资源，带三角函数上下文 |
| 问教材（正在聊三角函数） | "找一份英语试卷" | 第二关：找+试卷→找资源，英语和当前主题无关 | 转场到找资源，不带问教材上下文 |
| 问教材 | "生成一份光合作用课件" | 第二关：生成+课件→做课件，问教材没预设此路径 | 转场到做课件 |
| 问教材 | "今天天气怎么样" | 第三关：非教学，场景体系内无归属 | 通用能力回答，右侧工作台不动 |
| 找资源（正在找数学试卷） | "三角函数是什么" | 第二关：纯知识理解→问教材的核心能力 | 转场到问教材 |
| 找资源（正在找数学试卷） | "难度再高一点" | 第一关：找资源的累积上下文跟进 | 场景内处理 |
| 找资源 | "据这份卷子出一份同类练习" | 第一关：找资源预设了跨场景流转到出卷子 | 场景内转场到出卷子，带资源上下文 |
| 出卷子 | "帮我翻译一句英语" | 第三关：非教学场景归属 | 通用能力回答，右侧工作台不动 |

## 7. 混合意图处理

用户输入经常不是单一任务。路由策略不能只做一次硬分类，而要识别主任务并为次要意图提供后续出口。

### 7.1 知识 + 资源

如"三角函数有哪些重点？有没有相关课件？"——先调起问教材回答知识重点，回答底部提供"查看相关资源"后续动作。用户点击后转场到找资源。

### 7.2 知识 + 教学方法

如"三角函数怎么讲？"——更偏方法指导，但需要依赖知识理解。可进入方法指导场景（或问教材的教学设计启发型），同时调用知识解析作为基础。

### 7.3 知识 + 生成产物

如"把三角函数整理成讲义"——主任务是生成讲义，知识内容是素材。优先调起生成类工作台。

### 7.4 资源 + 生成

如"找一份三角函数试卷，找不到就帮我出一份"——先进找资源，结果不满意时底部提供"直接生成"流转入口。

### 7.5 处理原则

- 识别主任务，优先调起主任务对应的工作台；
- 次要意图通过回答底部的后续动作或跟进建议覆盖，不强行二选一；
- 当无法判断主次时，按 §5.1 的优先级决定首选场景，同时在回答中提供替代方向。

## 8. 路由输出格式

建议路由模块输出结构化结果，供后续逻辑调用。

```
{
  action: "open_workspace" | "stay" | "general_response",
  target_scene: "找资源" | "问教材" | "出卷子" | ... | null,
  confidence: 0.97,
  basis: ["命中资源检索意图：找+试卷", "提取学科：数学，学段：七年级"],
  carry_context: true,
  context: {
    subject: "数学",
    grade: "七年级",
    topic: "有理数",
    source_scene: "问教材",
    textbook: "人教版·七年级·上册"
  },
  secondary_intents: ["资源推荐"],
  followup_suggestions: ["查看相关课件", "生成知识卡片"]
}
```

| 字段 | 说明 |
| --- | --- |
| action | 三种动作：打开工作台、保持当前状态、通用回答 |
| target_scene | 目标场景，action 为 stay 或 general_response 时为 null |
| confidence | 置信度，用于决定自动调起还是引导选择 |
| basis | 判断依据，可用于调试和展示（如原型中的识别过程） |
| carry_context | 是否携带上下文到目标场景 |
| context | 传递的上下文内容 |
| secondary_intents | 次要意图，用于生成后续动作建议 |
| followup_suggestions | 推荐的后续动作 |

置信度阈值建议：

- 高置信度（≥ 0.8）：自动调起工作台；
- 中置信度（0.5~0.8）：左侧回答 + 引导用户确认场景方向；
- 低置信度（< 0.5）：左侧直接回答，不调起工作台。

## 9. 设计决策

### 9.1 实现方案选型（待详细设计）

路由判断采用分层方案，与轻/重场景分层和 §3 的四关判断框架对应：

| 层级 | 技术方案 | 覆盖范围 | 特征 |
| --- | --- | --- | --- |
| 规则层 | 动作词 + 对象词组合匹配 | 明确命中重场景（"找一份试卷"→找资源，"出一份卷子"→出卷子） | 快、零成本、确定性高 |
| 分类层 | 轻量分类模型 | 区分重场景、轻场景、纯通用三类 | 快、低成本，处理规则层未命中的输入 |
| LLM 层 | 大语言模型 | 混合意图、模糊输入、需要理解上下文才能判断的情况 | 灵活但慢，只处理前两层无法决策的输入 |

分层的调用逻辑：规则层先过，命中则直接执行；未命中交给分类层；分类层置信度不够时升级到 LLM 层。具体的规则库、分类模型训练数据、LLM prompt 设计需要单独出技术方案。

### 9.2 轻场景的定义与归属（已决策）

方法指导、写作文辅导、实验指导等任务归入轻场景（见 §2.1）。

**决策依据：** 这类任务有明确的教学属性，不能当纯通用处理，但又不需要专用工作台 UI——它们以对话驱动为主，产出物（文档、导图等）通过通用产出面板展示即可。为每个这类任务建独立重场景会导致场景过多、不聚焦，且开发成本高。

**轻场景的完整行为定义：**

- 路由识别后，左上角更新为"正在陪你·写作文"等，与重场景感知一致；
- 右侧顶部不出现专用 tab；
- 对话过程中，右侧展示轻量过程态（如"正在帮你写作文…"）；
- 产出物生成后，右侧通用产出面板展示结果，支持编辑、下载等；
- 不需要手动退出，用户发起新任务时自动切换，或连续无关对话后自动回首页（见 §9.5）。

**轻场景与问教材的关系：** 部分轻场景（如方法指导）和问教材有交叉——问教材已定义了"教学设计启发型""课堂讲解型"等问题类型。当用户在问教材工作台内发起方法指导类问题时，由问教材场景内处理（第一关命中）；当用户在无工作台状态或其他场景下发起时，作为独立轻场景处理。

### 9.3 通用问答的定位（已决策）

通用问答是三层结构的最底层：

```
重场景（有专用工作台）
  → 轻场景（无专用工作台，有特定回答策略）
    → 纯通用（无教学任务属性，直接回答）
```

纯通用处理的输入：闲聊、非教学问题（"今天天气怎么样"）、路由无法判断归属的模糊输入。

通用问答的设计原则：

- 保持助手人格一致（友好、专业的教学助手）；
- 对非教学问题简洁回答，不过度发挥；
- 当输入接近教学边界但不够明确时，回答的同时引导用户可选的场景方向（"如果你想深入了解这个知识点，可以试试问教材"）；
- 不主动推销场景，只在有关联时自然引导。

通用问答的回答风格和引导策略的具体设计，待上线后根据实际兜底输入的分布补充。

### 9.4 置信度阈值的校准（待数据支撑）

§8 中的置信度阈值（0.8 / 0.5）为初始经验值，需要用真实用户对话数据跑一批后校准。可从现有对话记录中提取典型输入，标注期望路由结果，作为校准基准。

### 9.5 工作台自动回首页（已决策）

当用户连续多轮对话命中第三关（场景外临时响应），触发工作台自动回到场景选择首页。

**触发机制：** 复用 §3.2 的四关判断框架——每轮对话如果命中第一关（场景内处理）或第二关（转场到其他场景），不计数；命中第三关（场景外临时响应）计一次；连续 3 轮命中第三关，触发回首页。

**回首页时的行为：**

- 右侧工作台回到场景选择首页；
- 左上角恢复为"有问必答 · 全程陪伴"；
- 对话中不需要插入系统提示（静默回收，不打断对话）；
- 左侧对话线索不中断。

**边界情况：** 场景内的内容补充式提问（如出卷子场景下用户说"我教的是初二"）不会被误判——这类输入属于当前场景的能力范围（接受用户补充信息），由第一关捕获，不会漏到第三关。前提是场景 agent 的 prompt 设计覆盖了"接受上下文补充"这类输入。

**N=3 为初始值**，上线后根据数据校准。1 轮太敏感（随口一句闲聊就回收），5 轮太迟钝。

## 10. 评估与迭代机制

### 10.1 核心指标

| 指标 | 含义 | 数据来源 |
| --- | --- | --- |
| 场景命中准确率 | 自动调起的工作台是否符合用户意图 | 用户行为：调起后是否立即手动切换到另一个场景 |
| 用户手动纠正率 | 系统判断后用户主动切换场景的比例 | 手动切换事件 / 总路由事件 |
| 通用兜底占比 | 未命中任何场景的输入比例 | 路由结果统计 |
| 后续动作点击率 | 回答底部的后续动作是否有效 | 点击事件 |
| 转场上下文利用率 | 转场后携带的上下文是否被目标场景实际使用 | 目标场景是否引用了传递的学科/主题/教材等字段 |

### 10.2 迭代机制

建议每月从以下样本中抽样复核：

- 被路由到通用问答但后续表现出教学意图的会话；
- 用户手动切换场景的会话（尤其是自动调起后立即切换的）；
- 回答后立即重新提问或纠正系统理解的会话；
- 多场景混合输入的会话；
- 短关键词输入的路由结果分布。

### 10.3 路由过程的透明度

原型中已实现路由过程的可视化展示（理解需求 → 提取关键信息 → 检索学科网权威库 → 识别场景 97%）。建议上线版本保留此设计，让用户看到系统的理解过程，建立信任感。当路由判断有误时，透明展示也便于用户理解为什么被带到了某个场景，降低挫败感。
