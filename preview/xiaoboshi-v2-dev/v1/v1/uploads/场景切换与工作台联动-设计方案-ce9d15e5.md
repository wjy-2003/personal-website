# 场景切换与工作台联动 设计方案

> 用途：① 与开发对齐场景路由与状态管理逻辑；② 交给 Claude Design 按第 5 节修改对话工作台原型。
> 日期：2026-07-09
> 状态：方案已收敛，开放问题见第 6 节

## 1. 背景与问题

### 1.1 产品骨架

小博士的核心骨架是：**一个入口 → 一次识别 → N 个工作台 → 一条贯穿会话**。

- 首页只有一个输入框，AI 自动识别用户意图，路由到对应场景（找资源、出卷子、做课件、写教案、问教材、画导图、改作业等）
- 进入对话后，页面为左右分栏：左侧是对话流，右侧是当前场景的工作台面板
- 场景切换**不销毁对话**：一条会话可以贯穿多个场景工作台

### 1.2 现状

- 首页：全部场景入口以胶囊按钮排列在输入框下方
- 对话工作台页：场景入口以一排 tab 放在**右侧面板顶部**，当前场景高亮

### 1.3 现状的三个问题

1. **操作动线断裂**：用户在左下角输入框打字，切场景却要移动到右上角，输入与模式选择不在同一视觉焦点区
2. **控制范围歧义**：tab 放在右侧面板内部，视觉上暗示「只控制右边这块区域」，但场景实际是整个会话的属性（左侧对话流也随之变化）
3. **同一组件两种语义**：首页胶囊是「选场景开始」，工作台 tab 是「切场景」，两处视觉相同但行为语义不同，用户预期会混乱

## 2. 核心模型：会话状态模型

这是整个方案的地基，开发和设计都需要先理解这一节。

### 2.1 不做「用户锁定」模型

锁定模型指：用户选中场景 = 锁定「接下来都按这个场景处理」。该模型与「对话中途 AI 自动识别切换」直接冲突（用户锁了找资源，AI 又能自动切走，锁定失去意义），**弃用**。

### 2.2 会话状态模型定义

系统只有一个状态变量：**会话当前场景**。

- 会话任何时刻都处于某个场景中
- 该状态由「最近一次路由」决定，路由有两个触发源，**地位平等**：
	- AI 意图识别（每条消息触发）
	- 用户手动点击场景胶囊
- 手动点击**绕过分类器直接改写状态**，不经过识别，也不存在置信度（置信度只在识别一条消息时短暂存在）

### 2.3 状态的两个下游投影

「先验」和「右侧面板」都不是独立决策，它们是当前场景状态的两个下游，状态一变则同时变：

- **识别先验**：路由决策读取当前场景，作为下一条消息识别的偏置输入
- **右侧工作台面板**：当前场景的视图渲染

因此「手动切换后右侧面板要不要跟着变」不是一个问题——面板是状态的投影，状态变了面板必然变。

### 2.4 场景状态无损保留

各场景的工作台状态（结果列表、配置项、中间产物）挂在会话上，切走后保留，切回时无损恢复。右侧面板的本质是**同一会话下 N 个场景工作台的切换视图**。

这条规则同时解决了「浏览」问题：切换成本趋近于零（切过去看一眼冷启动页，一键切回、状态无损），切换本身就是浏览，不需要额外的预览层。

## 3. 路由规则（逐条消息）

### 3.1 基本流程

每条消息都过一次意图识别，无论当前处于什么场景。这不是额外成本——支持中途自动切换的前提就是逐条识别，手动选中并不能省掉它。识别输出各场景的置信度分布，再结合先验做决策。

### 3.2 非对称阈值

核心原则：**留下不需要证据，切走需要强证据。**

| 识别结果 | 处理方式 |
| --- | --- |
| 其他场景置信度高（> T_high，暂定 0.8） | 自动切换 + 对话流轻提示 + 一键切回 |
| 其他场景置信度中等 | 留在当前场景处理 + 回复中软引导「如果想 XX，可以切到 XX 场景」 |
| 置信度低 / 指向当前场景 | 留在当前场景直接处理 |

- 会话首条消息无先验，取置信度最高的场景，门槛可以低
- 会话中途切换的门槛显著高于首条

### 3.3 示例

以下均假设当前场景为「找资源」：

- 「再来几道类似的」→ 省略语境的追问，置信度低 → 留守找资源
- 「帮我出一套有理数的卷子」→ 高置信指向出卷子 → 按 3.2 自动切换（若处于豁免期则按第 4 节处理）
- 「有理数的题」→ 中间地带 → 留守找资源返回题目资源，回复中软引导「想出成卷子可以切到出卷子」

## 4. 手动切换与豁免机制

### 4.1 需要解决的矛盾

用户刚刚手动选了场景，紧接着的输入却指向其他场景。此时静默自动切走等于无视用户一秒钟前的明确表态，体验刺眼。

### 4.2 状态字段

系统为会话维护两个字段：

- `场景来源`：manual / auto
- `切换后消息数`：当前场景激活以来用户发送的消息数

**豁免条件**：`场景来源 = manual` 且 `切换后消息数 = 0`，即手动切换后的第一条消息。按消息计数判断，**不用计时器**（用户选完场景离开再回来，语境上仍是「刚选完」，消息计数天然覆盖）。

### 4.3 豁免期处理规则

豁免期内识别到高置信度的其他场景意图时，**不自动切换**，按当前场景能否消化分两支：

**分支一：当前场景可给出合理响应** → 场景内响应 + 结果上方放切换引导。

示例：用户手动选了找资源，输入「帮我出一套有理数的卷子」。「出卷子」既可理解为找现成的（找资源可消化），也可理解为新生成（出卷子场景）。用户刚选了找资源，该动作即语境 → 返回现成的有理数试卷，结果上方提示「想让我按你的要求新出一套？切到出卷子 →」。

**分支二：当前场景无法消化** → 不硬答，给确认卡一键切换。

示例：用户手动选了找资源，输入「帮我批改这份作业」。找资源做不了批改 → 确认卡「这个需求需要用改作业来处理，切换吗？」。

### 4.4 豁免的消耗与恢复

- 豁免为**一次性**：第一条消息发出后即消耗，无论触发了什么
- 从第二条消息起，恢复第 3 节的标准非对称阈值规则
- 豁免结束后再次出现高置信不一致输入 → 直接自动切换。依据：用户上一条已见过切换引导却未切，本条又发出明确指向其他场景的内容，两次信号叠加足够硬；且误切代价被「一键切回 + 状态无损」兜底
- 用户点击引导/确认卡完成切换 = 新的手动切换，重新获得一条消息的豁免期

## 5. 交互改动清单（原型修改需求）

改动对象：**对话工作台页**（左侧对话流 + 右侧场景面板的分栏页面）。首页不改动。

### 5.1 撤掉右侧面板顶部的场景 tab 行

右侧面板顶部替换为**当前场景标题**（如「🔍 找资源」），只承担「你在哪」的状态标识，不再承担切换职责。

### 5.2 场景切换入口移至对话输入框区域

- 形态：**胶囊平铺**——输入框上方一行场景胶囊，当前场景呈高亮选中态
- 溢出规则：一行放不下的场景收进「更多」展开项；若当前场景恰好属于收起集合，将其交换到可见位（当前场景必须始终可见）
- 点击胶囊即切换，等价于一次手动切换事件（写入 `场景来源 = manual`）
- 视觉上与首页胶囊保持同一设计语言，但需注意两处语义不同（首页 = 选场景开始，对话页 = 切换当前会话场景）

### 5.3 手动切换的联动行为

- 右侧面板立即切换到目标场景：有历史状态则恢复，无则展示该场景冷启动页（含引导文案与配置项）
- 左侧对话流保留，不清空、不新建会话

### 5.4 AI 自动切换的联动行为

- 右侧面板切换到目标场景
- 对话流中插入一条轻提示：「已切换到出卷子（切回找资源）」，「切回」为一键操作（等价于手动切换回原场景）

### 5.5 场景状态无损

各场景工作台的状态（结果列表、筛选配置、中间产物）在会话内保留，切换往返不丢失。

### 5.6 输入框 placeholder 跟随当前场景

切到哪个场景，placeholder 换成该场景的示例输入（现有原型已具备此逻辑，保持）。

### 5.7 状态条与胶囊联动

页面左上「正在陪你 · 找资源」状态条与输入区胶囊选中态来自同一状态源，任何切换（手动/自动）两处同步更新。

## 6. 开放问题（待开发对齐）

1. T_high / 中低置信度分界的具体取值，需要拿真实对话数据调参
2. 中置信度软引导的文案策略与出现频率控制（避免每条回复都在劝用户切场景）
3. 「更多」收纳的场景取舍：固定顺序，还是按用户记忆/使用频率动态排序
4. 移动端的胶囊平铺形态如何降级
5. 埋点：场景切换事件需记录来源（manual / auto）与方向；**切回率**作为自动切换误判的核心指标
