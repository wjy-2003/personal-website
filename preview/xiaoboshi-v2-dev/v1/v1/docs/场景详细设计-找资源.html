PART A · 业务流程

找资源端到端业务流程

找资源是小博士的「已有资源检索」场景，对应学科网作为资源聚合平台的底座能力。教师的核心诉求是从已有成品资源中，快速找到贴合班级学情的文档、视频、成套专辑，并据此收藏、下载，或直接流转到生成类场景。

1场景定位与边界

找资源是小博士的已有成品资源检索场景：用户已经知道自己要一份现成的东西，系统的职责是从学科网资源库（及用户自己的内容、资源篮）里把贴合学情的成品找出来并整理呈现，而不是新建、也不是讲解知识。一句话定位——「要现成的，来找资源」。

纳入与不纳入

维度找资源负责不在本场景
用户当前要什么已有成品资源（文档 / 视频 / 成套专辑）新建一份资源 · 对知识点的理解
典型输入「找一份三角函数试卷」「下载光合作用课件」「出一份三角函数卷子」「三角函数是什么」
系统产出检索整理出的资源列表（冻结为可回看轮次）AI 生成的新产物 · 结构化知识回答
不做什么不原创内容、不做知识讲解、不替用户决定排序之外的取舍——只检索、整理、呈现已有资源。

与相邻场景的边界

找资源真正要划清的是「要现成的」与「要新生成的 / 要知识解答的」之间的界：

相邻场景区别（它要什么）衔接关系
问教材要对知识点的直接理解，而非成品文件问教材回答底部「查看相关资源」可流入找资源
出卷子 写教案 做课件要 AI 新生成一份资源，而非检索已有已有资源不合适时，「直接生成」可流出到这些场景（见 §6）

边界是衔接而非互斥：用户常先找现成的、不满意再让 AI 生成，或先问懂知识点再去找配套资源。全局意图路由负责在这几端之间分发（见 §4）。
覆盖范围：从全局路由命中找资源（或用户主动进入）开始，到一次检索结果呈现并提供资源操作与跨场景流转为止，包含正常链路与异常分支。

2端到端流程总览

一次完整交互由前台交互层、意图路由层、内部处理层三段组成。主线如下：

1

用户入口

点「找资源」 / 路由命中 / 从问教材「查看相关资源」流入。

2

冷启动或带需求进入

无输入 → 冷启动面板（个性化示例 / 热门检索 / 分类示例）；有输入 → 直接进入检索。

3

检索意图解析

把需求转化为结构化条件：资源形态 · 学科 · 学段 · 版本 · 类型 · 难度 · 主题。

4

追问 / 澄清判断（设想）

仅当需求宽到结果噪声过大才发起一轮追问；否则用累积上下文先给一批。

5

多源检索与排序

学科网库 / 我的内容 / 资源篮 → 打来源标签 → 排序 → 冻结为一轮 round。

6

结果分轨呈现

全部 / 文档 / 视频 / 专辑 + 来源标签 + 筛选项；内容感知回复 + 跟进建议。

7

资源操作与流转

预览 / 播放 / 看专辑 / 收藏入篮 / 下载 / 详情页追问；不合适则直接生成（HANDOFF）。

3前台交互层

3.1 场景入口（三条路径）

  • 用户主动点击首页「找资源」入口；
  • 在通用输入框输入带资源检索意图的句子，由全局意图路由命中找资源；
  • 从问教材回答底部「查看相关资源」流入，带着上一轮学科 / 主题上下文进入。

三条路径汇合后进入同一套内部处理链路，采用「左侧对话 + 右侧结果舞台」的双栏工作台形态，顶部场景切换栏可切到其他场景。

3.2 冷启动面板（无输入进入）

教师进入但还没有输入时，展示冷启动面板，引导用一句话描述需求，并说明结果会涵盖文档、视频、成套专辑三类。面板内容随登录态分化：

登录态顶部横幅推荐区分类示例
已登录（有记忆画像）已结合记忆（如人教版·七年级·数学）推荐「为你推荐」——按画像挑选贴合你的班级 / 你常找的视频 / 成套备课专辑
未登录提示登录后推荐更懂你「热门检索」——大家都在找文档（教案/课件/卷子）/ 视频（实验/微课）/ 专辑（成套合集）

冷启动示例和热门词均可点击直接发起一轮检索。

3.3 输入与累积上下文

输入框接受自然语言需求。系统从输入中识别学科、学段、资源形态，并把识别到的学科 / 学段累积记忆到当前会话上下文，使后续模糊追问（「难度再高一点」「只要含答案的文档」）也能正确解析。

4意图路由层

全局意图路由是所有场景之前的前置分发层，综合动作词、资源词、学科词、附件类型、上下文历史判断主场景。与找资源直接相关的判定：

路由结果命中条件典型输入
命中找资源含 找、下载、有没有、资源、试卷、课件 等检索意图「找一份三角函数试卷」
不命中（生成）明确要求生成课件 / 教案 / 卷子 / 讲义「生成一份三角函数课件」
不命中（问教材）问概念 / 定理 / 原因 / 区别 / 教材内容理解「三角函数是什么」
不命中（通用兜底）非教学、闲聊、无法判断「今天天气怎么样」
优先级与混合意图找资源（明确资源检索）排在明确文件处理、明确生成类之后，问教材、方法指导之前。「知识 + 资源」混合（如「三角函数有哪些重点？有没有相关课件？」）先问教材回答重点，再提供相关资源入口——先问教材、后找资源衔接。详见 主文档 §2.2 意图识别与分类。

5内部处理层

5.1 检索意图解析

命中后不再判断「是不是要找资源」，而是把需求转化为多源检索所需的结构化条件：

解析要素用途来源
资源形态决定结果分轨（文档 / 视频 / 专辑 / 全部混合）关键词：含「专辑/合集/套/打包」→ 专辑；含「视频/实验/研修/微课」→ 视频；否则全部混合
学科限定检索范围从输入识别，识别不到取累积上下文
学段 / 年级限定检索范围从输入识别，识别不到取累积上下文
版本筛选条件输入或筛选器（人教版 / 北师大版 / 通用…）
资源类型筛选条件课件 / 教案 / 学案 / 作业 / 试卷 / 题集 / 素材…（对齐标签树一级类型）
难度筛选条件基础 / 中等 / 拔高
知识主题检索核心对象输入中的知识点或《书名》

5.2 追问 / 澄清判断

当需求信息不足以精准检索时（核心是学科未知），先发起一轮澄清再检索；其余情况默认「先用累积上下文给一批」不打断。是否追问与登录态相关：已登录（有记忆画像）默认已知学科学段，几乎不追问；未登录或无画像时，宽泛输入会触发追问。

当前情况是否追问处理方式
学科可提取（输入含学科词 / 已登录有画像）否直接检索
找资源意图但学科未知（如未登录时「帮我找点试卷」）是一轮澄清：学段必选 → 学科必选（选项随学段变）→ 年级选填，保留自由输入
模糊跟进（「难度再高一点」「有没有相关课件」）否用已确认的累积上下文 + 新条件，直接出新一轮
同一会话已追问过一次否最多一轮：学科已确认（subjectConfirmed）后不再追问

追问原则与问教材一致：最多一轮、动态生成选项、保留自由输入；放弃补全则用现有上下文先给一批。原型已实现：未登录进入找资源、输入「帮我找点试卷」后，小博士先回一句「已识别你要找试卷、但还缺学科学段」的铺垫，随即从输入框上方上拉浮现追问弹框（Claude AskUserQuestion 式）。弹框按依赖顺序展开：先选学段（必选，小学 / 初中 / 高中）——因为学段决定了可选的学科与年级——再选学科（必选，选项随学段变，支持键盘 1–9 选学科）与年级（选填，如初中→七 / 八 / 九年级）；回车确认 / Esc 跳过 / 也可直接在输入框自己描述，对话停在等待选择状态；选定后在 AI 回复里补一张紧凑的「已答」摘要卡（问题 + 所选「初中 · 物理」），随后照常出检索结果——既利落又保住会话连续性。已登录（记忆画像提供学科学段）则不追问。可在 Tweaks 面板关闭「已登录」来复现。

5.3 多源检索与排序

检索从三个来源取数，构成一轮混合结果，按固定优先级重排：

来源含义排序权重
我的内容登录用户自己上传 / 拥有的资源最高（排最前）
资源篮用户已收藏进资源篮的资源次高
学科网学科网资源库的公共成品资源基础

按资源形态决定混排比例（「全部」默认约 2 专辑 + 8 文档 + 3 视频，单轮上限约 14 项）；按学科 / 学段过滤，过滤后为空时逐级放宽（先放宽学段，再放宽学科）保证不空手而归。

结果冻结、可回看 ——「给你了就是你的」每次检索产出一个冻结的结果集（round）：每条 AI 回复携带它那一轮的 id，点击该回复下方的结果入口可精确重开那一轮结果，历史轮次永不被覆盖。这是找资源区别于普通搜索框的关键交互模型。

5.4 结果呈现

检索过程中右侧先展示「正在从学科网资源库检索匹配…」的骨架占位，确保结果不早于 AI 回复出现。完成后：

  • AI 回复说明本轮理解（如「理解为七年级数学」）、检索总数、其中多少来自你的内容 / 资源篮收藏；
  • 回复下方挂一个结果入口「已为你匹配 N 个资源」，点击查看本轮结果；
  • 右侧结果舞台按轨道分页：全部 / 文档 / 视频 / 专辑；每张卡片带来源标签和关键字段（版本、学段学科、难度、题量 / 页数、匹配度、是否已审校等）；
  • 提供更多筛选：学段 / 学科 / 版本 / 类型 / 难度；回复区给出贴合当前结果形态的跟进建议。

资源回复是内容感知的：基于资源 / 视频的真实字段自洽生成（视频说明分章节、时长、画质、适合环节；文档说明页数、题量、覆盖知识点、是否审校），不空泛吹捧。

6资源操作与跨场景流转

用户对单个资源可执行：预览（文档）/ 播放（视频，按章节跳转）/ 展开专辑 / 收藏入篮 / 下载 / 追问该资源（见 §7）。收藏后该资源在后续轮次会带「资源篮」来源标签并优先排序。

找资源的出口不止于「找到」。当已有资源不完全合适时，提供直接生成的流转入口（HANDOFF），把当前检索上下文（知识点、难度、学段学科）带到生成类场景：

流转动作去向说明
直接出一份卷子出卷子从学科网题库按当前知识点和难度智能组卷
生成配套教案写教案对齐课标的教学设计
做成课件做课件结构清晰的 PPT
handoff 含义切换到另一个生成场景只改右侧面板，左侧对话线索不中断——用户感知为「同一位助手继续」，不是新开会话。详见 主文档 §2.4 会话与多轮迭代模型。

PART B · 详情页交互

资源详情页「问小博士」问题列表

用户进入资源详情页（文档预览 / 视频播放 / 专辑页）后，底部「问小博士」给出一组按资源类别预设的问题入口。本节定义其交互逻辑、问题配置策略与后端处理方案。

7.1核心交互原则

遵循「一条会话贯穿」产品原则：用户点击详情页的问题，消息发送到左侧对话面板（现有对话），不开新会话、不切换场景，找资源的历史对话线索不中断。右侧面板保持显示资源详情，场景标识仍是「找资源」。后端处理路径不同（见 §7.4），但对用户透明——感知为「同一位助手回答了资源相关问题」。

消息气泡上方的资源引用卡片

消息在左侧对话中显示时，气泡上方以独立引用块形式显示资源引用卡片（资源标题 + 类别），让用户清楚这条问题针对哪份资源。点击引用卡片：该资源已在右侧打开 → 提示「已打开」；未打开 → 右侧面板重新打开该资源详情。若该引用是在出卷子 / 写教案等生成场景里（由 C 类 handoff 带入），点击则跳回找资源并打开该资源；配合输入框上方的会话任务条（见 §7.4）可随时一键切回草稿。

假期作业「据此出一份同类练习」C
专辑「这个合集涵盖哪些知识主题」（针对集合整体）A
展示规则题组上限 = 2 固定 + 2 动态 = 最多 4 个。某条件不满足（记忆系统未就绪 / 无字幕）→ 对应问题入口隐藏、不占位。试卷 / 题集 / 作业等含多题的资料不用「这道题怎么讲」——一份试卷里题太多，直接问「这道题」小博士无法定位是哪道；改为「挑几道典型题讲讲」，由 AI 从原卷选题讲解（用户也可补一句「第几题」逐题讲）。专辑详情页只展示专辑级问题，不展示子资源各自的问题入口；专辑详情页按 单元 → 课文 / 专题 → 资料 的层级全量展开（资料行只列文档类），子资源点击后进入该子资源的资料详情页，按其普通资料类型展示对应问题，与专辑无关。

7.3点击后的前端处理

1

打包资源上下文进消息体

资源 ID、标题、类别、学科、学段、难度、版本，如有则附内容摘要 / 前 N 段正文 / 视频字幕片段，加来源标记字段 source: "resource_detail"。

2

左侧对话展示引用卡片 + 问题

气泡上方独立引用块显示资源标题 + 类别；引用卡片可点击重开 / 提示已打开。

3

后端按来源标记与问题类型走不同路径

识别为「资源详情发来的消息」，不触发 search_resources 资源搜索流程，按 A / B / C 三类处理。

关键防误触发消息打包了资源上下文，后端需能区分「资源详情发来的消息」与「用户手打的普通消息」，避免意外触发资源搜索。产品层设计为在消息体中加来源标记字段（source: "resource_detail"）；具体实现（消息体字段或 header）由开发决定。

7.4后端处理方式（三类）

A内容 RAG 类

基于资源正文回答

适用问题总结考点 / 教学重点、讲题、提取教学目标 / 学习重点、总结视频要点、整理教学流程。
依赖资源正文文本（文档需 PDF / Word / PPT 解析；视频需字幕或转写文本）。
流程按 resource_id 查缓存 → 未命中则实时拉取解析并写缓存 → 截取相关段落（RAG 或全文）→ 注入 LLM 要求基于提供文本回答，不检索新资源。
解析策略首次实时解析 + 结果缓存；首个访问用户经历完整耗时，后续命中缓存。性能上线后测试，必要时改离线预处理。
降级正文不可用时基于标题 + 元数据作答，并注明「仅基于资源描述，未读取正文」。
B画像对比类

判断是否适合班级

适用问题这份适合我的班级吗？
依赖用户记忆系统的 tags（学科 / 学段 / 偏好难度）与资源元数据。
流程读取记忆 tags → 与资源学科 / 学段 / 难度对比 → LLM 输出判断 + 理由，不检索新资源、不需正文。
降级记忆系统未建设 → 前端隐藏此入口；已建设但当前用户无数据 → 展示入口，点击后在左侧对话提示用户补全学科 / 学段 / 难度偏好，回复后写入 tags。
C生成 handoff 类

据此生成新资源

适用问题据此出一份同类卷子 / 同类练习、据此生成教案。
依赖资源元数据（知识主题、学科、学段、难度）。
流程识别为生成 handoff → 提取资源知识主题 + 学科 + 学段 + 难度 → 右侧面板切换到对应生成场景（出卷子 / 写教案），携带上述参数；左侧对话线索不中断。
草稿保留handoff 产生的草稿处于未完成态；用户从资源详情切回后草稿不丢失——在找资源左侧输入框上方常驻一条「会话任务条」，一键回到该草稿。任务条有两种状态且样式区分：草稿条（虚线边框 / 灰底，编辑中）与结果条（实线 / 品牌浅底 + 绿点，已成稿）。

PART C · 落地实现

系统架构、里程碑与实现状态

找资源里 LLM 不负责「找」。真正把资源找出来的是学科网的检索 / 推荐服务，LLM 只做三件事：理解意图、编排检索、叙述结果。约 80% 的工作量在数据与检索底座，系统提示词是最薄、最后、最易改的一层。一句话原则：先把数据和检索做实，再写 Agent 和提示词。

8系统架构与里程碑

8.1 四层架构（职责严格分离）

路由层 · LLM 触点①
全局意图路由：这句话进不进「找资源」
▼ 命中找资源
Agent 层 · LLM 触点②（核心）
解析需求 → 判断追问 / 检索 → 调工具 → 叙述 → handoff
▼ 调 search_resources
检索层 · 确定性工程
多源检索 · 打来源标签 · 排序 · 放宽 · 冻结 round
▼ 依赖
数据层
资源元数据库 + 三源（学科网 / 我的内容 / 资源篮）
关键分工纪律排序、过滤放宽、round 冻结一律是确定性代码，不交给 LLM，否则优先级与「给你了就是你的」冻结契约会不稳定；LLM 只读检索结果、不做计算，它叙述结果，但不决定哪些资源排前面。

阶段核心产出说明

8.3 匹配度（match）计算

匹配度是检索层计算好后挂在每条资源上返回的字段（0~100 整数），前端直接展示圆环，Agent 层只读引用、不做二次计算。两层叠加：字段精确匹配（0~60，确定性代码）——学科 / 学段 / 难度 / 版本 / 类型逐项命中加分；语义相似度（0~40，向量计算）——用户知识主题与「资源标题 + 知识点 tag」做 Embedding 余弦相似度。向量在资源入库时预计算存储。

原型现状 / 最简落地data.jsx 里的 match（98、95、92…）是写死的 mock。真实系统若 Embedding 短期成本高，可先只做第一层字段精确匹配跑通链路，后续再叠加向量层。提示词中可自然引用 match，但不得自行估算或编造该数值。

8.4 三处 LLM 触点

「系统提示词」不是一个，是三个触点，不要用一个大 prompt 包圆（避免上下文污染、职责混乱，且各触点可独立选型）。

触点所在层职责形态
① 全局路由路由层判断进不进找资源分类 prompt 或轻量模型
② 找资源 Agent（主方案）Agent 层解析 + 追问决策 + 叙述 + handoff，LLM 为控制中枢system prompt + 函数调用工具
② 独立抽取（备选）Agent 层解析→代码判断→调检索→LLM 叙述，代码为控制中枢三段独立 prompt，代码串联

系统提示词草稿（路由、Agent、回复生成、意图抽取等）见《找资源场景-实现步骤与系统提示词》原文，上线前需结合真实数据与模型表现迭代。

9异常分支与关键原则

9.1 异常与边界分支

分支系统处理用户提示
未登录「我的内容」不可用，记忆个性化降级为热门检索提示登录后推荐更懂你、可保存资源篮
过滤后为空逐级放宽（先学段、再学科）兜底出一批说明已放宽范围，可继续加筛选
完全无匹配（设想）不空手，回到示例引导或建议改写需求提示换个说法或直接生成
资源形态识别错误（设想）提供轨道切换与跟进建议快速纠偏「只看视频」「有没有成套专辑」一键跟进
下载 / 收藏需登录拦截并引导登录提示登录后可收藏到资源篮、下载
路由误判轻量确认或允许切换到问教材允许手动切换场景

9.2 关键原则回顾

①

结果冻结、可回看

每轮检索是不可变结果集，历史轮次永不覆盖，回复入口可精确重开——「给你了就是你的」。

②

多源优先级

我的内容 > 资源篮 > 学科网，让用户自己的和收藏的资源优先露出。

③

不空手而归

过滤无命中时逐级放宽，宁可放宽范围也不返回空列表，配合明确范围说明。

④

检索与生成连续

找资源不是终点，资源不合适时一键流转到出卷子 / 写教案 / 做课件。
